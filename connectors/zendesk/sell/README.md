# Zendesk Sell connector

The Go, Python, and TypeScript connectors read lead identities through `listLeads` and `getLead`. Go also offers `createLead`, `updateLead`, and `deleteLead`. Results exclude custom fields, addresses, activity, and provider links from Flow state. These operations support Sell workflows and data migration.

Sign in to [Zendesk Sell](https://app.futuresimple.com/) with account management privileges, then open Integrations > OAuth > Access Tokens. Add a User Token and copy its one-time value into Dex secret `access_token`. The connector sends it in an `Authorization: Bearer` header. The API root defaults to `https://api.getbase.com/v2`. See the [Sell authentication guide](https://developer.zendesk.com/documentation/sales-crm/first-call/) and [Leads API](https://developer.zendesk.com/api-reference/sales-crm/resources/leads/). Runnable consumers: [Go](go/examples/lead-discovery/README.md), [Python](python/examples/lead_discovery/README.md), and [TypeScript](typescript/examples/lead-discovery/README.md).

Both Queries retry transport errors, HTTP 429, request timeout, and server failures. `getLead` selects `notFound` on a definitive 404. `updateLead` and `deleteLead` safely repeat absolute writes after an unknown outcome. `createLead` may produce a duplicate after a lost response: its single-dispatch fence allows at most three possible sends, then selects `uncertain` when the create cannot be confirmed. It does not infer success from a lead name or email because neither uniquely identifies this request. Provider rejections and malformed or oversized query responses select optional branches. An unwired optional branch fails the Flow. The Go lead-intake example uses a deterministic mock; live provider authorization and responses have not been exercised.

Zendesk [plans to retire Sell on August 31, 2027](https://support.zendesk.com/hc/en-us/articles/9591462550042-Announcing-the-retiring-of-Zendesk-Sell). Existing customers retain access until then; new integrations should account for migration.

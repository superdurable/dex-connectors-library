# Zendesk Sell connector

The Go, Python, and TypeScript connectors read lead identities through `listLeads` and `getLead`. Go also offers `createLead`, `updateLead`, and `deleteLead`, plus `listRecords`, `getRecord`, `createRecord`, `updateRecord`, and `deleteRecord` for contacts, deals, tasks, and notes. The record operations select a resource with `sell.SellContacts`, `sell.SellDeals`, `sell.SellTasks`, or `sell.SellNotes`. Write `Fields` with the selected resource's [Sell API v2](https://developer.zendesk.com/api-reference/sales-crm/resources/introduction/) JSON field names; the connector rejects unknown names and malformed JSON. Create a contact with `last_name` or organization `name`, a deal with `name`, a task with `content`, and a note with `content`, `resource_type`, and `resource_id`. Results retain identity and common fields, excluding custom fields, addresses, activity, and provider links from Flow state.

Sign in to [Zendesk Sell](https://app.futuresimple.com/) with account management privileges, then open Integrations > OAuth > Access Tokens. Add a User Token and copy its one-time value into Dex secret `access_token`. The connector sends it in an `Authorization: Bearer` header. The API root defaults to `https://api.getbase.com/v2`. See the [Sell authentication guide](https://developer.zendesk.com/documentation/sales-crm/first-call/) and [Leads API](https://developer.zendesk.com/api-reference/sales-crm/resources/leads/). Runnable consumers: [Go](go/examples/lead-discovery/README.md), [Python](python/examples/lead_discovery/README.md), and [TypeScript](typescript/examples/lead-discovery/README.md).

Queries retry transport errors, HTTP 429, request timeout, and server failures. `getLead` and `getRecord` select `notFound` on a definitive 404. Updates and deletes safely repeat absolute writes after an unknown outcome. `createLead` and `createRecord` may produce a duplicate after a lost response: their single-dispatch fences allow at most three possible sends, then select `uncertain` when the create cannot be confirmed. They do not infer success from user-chosen names or email because those values do not uniquely identify this request. Provider rejections and malformed or oversized query responses select optional branches. An unwired optional branch fails the Flow. The [Go example](go/examples/lead-discovery/README.md) includes lead and record intake with deterministic mocks; live provider authorization and responses have not been exercised.

Zendesk [plans to retire Sell on August 31, 2027](https://support.zendesk.com/hc/en-us/articles/9591462550042-Announcing-the-retiring-of-Zendesk-Sell). Existing customers retain access until then; new integrations should account for migration.

# Odoo connector

The Go, Python, and TypeScript `searchPartners` Query calls Odoo 19's [JSON-2 `res.partner/search_read`](https://www.odoo.com/documentation/19.0/developer/reference/external_api.html) method once per Flow Step. It searches company partners by an Odoo `ilike` name pattern and returns only their numeric IDs and names. Go also lists, reads, creates, updates, and deletes contacts through `res.partner`.

Go also lists, reads, creates, updates, and deletes CRM opportunities through `crm.lead`. List queries select records with `type=opportunity`; create sets that type explicitly. The title is required, while prospect email and phone may be blank. Creation uses the same three-send limited policy as contacts and reads back by exact title, email, and phone when an email is supplied. Update sets those three fields to absolute values. The API key's user needs CRM access for these operations.

Go `listRecords`, `getRecord`, `createRecord`, `updateRecord`, and `deleteRecord` provide model-specific JSON-2 CRUD for `res.partner`, `crm.lead`, `mail.activity`, and custom models beginning `x_`. This covers Odoo activities and custom resources without adding credentials or changing existing connections. The model name comes from your Odoo instance's **Technical > Database Structure > Models** page; the API key user needs access to that model. For an activity, use `mail.activity` and supply Odoo's required numeric `res_model_id`, `res_id`, and `activity_type_id` in `values` when creating it. Find the linked model ID on **Technical > Database Structure > Models**, the activity type ID under **Settings > Technical > Email > Activity Types**, and the linked record ID in its Odoo page URL. Supply JSON values in `values`, such as `{"summary":"Call customer","res_model_id":1,"res_id":42,"activity_type_id":4}`; do not put credentials or secret fields there. `readBackField` may name a stable supplied field for exact post-send read-back, or remain blank to use the send cap without read-back. Reads require an explicit list of one to twenty non-secret field names and return only those fields. Unsupported system models and secret-like field names fail validation. Updates set selected fields to absolute values; deletions are safe to repeat.

Odoo's JSON-2 API requires an Odoo 19 or newer deployment and an eligible external API plan. In Dex Web Connections, enter the site's HTTPS origin as `baseUrl`, without `/json/2`; enter the exact database name as `database`. On Odoo Online this is usually the subdomain before `.odoo.com`; an administrator can confirm it on other deployments. Generate a secret `apiKey` under your user avatar > **My Profile or Preferences > Account Security > New API Key**, choose a description and expiry, and copy it once. Give the dedicated user only the contact permissions needed by the operations you use. Leave `timeout` and `maxResponseBytes` blank for the displayed defaults.

Pass `namePattern` using Odoo `ilike` wildcards, such as `%Acme%`, and `limit` from 1 to 100. An empty match is a successful empty page. `listContacts` uses a limit from 1 to 100 and a zero-based offset. `getContact`, `updateContact`, and `deleteContact` use a positive numeric contact ID. `createContact` requires a name and supports email and phone; its limited retry policy allows at most three sends, reads back by exact name, email, and phone when email is supplied, and reports uncertainty if a write cannot be confirmed. `updateContact` sets the name, email, and phone to absolute values; blank email and phone clear those fields. Updates and deletion can safely repeat.

The [Go](go/examples/partner-search/README.md), [Python](python/examples/partner_search/README.md), and [TypeScript](typescript/examples/partner-search/README.md) examples use the static `odoo` connection. The Go example reads the first matched contact and lists activities. Live Odoo authorization and provider responses have not been verified.

# ActiveCampaign connector

The Go, Python, and TypeScript connectors list contact IDs, email addresses, and names with `listContacts` and retrieve one contact with `getContact`. Go also provides `syncContact` to create or update a contact by email, `updateContact` to replace selected fields by ID, `listLists` to page through email contact lists, and `getList` to inspect one list. List inputs are optional: omitted `offset` starts at the first page and omitted `limit` reads 20; 100 is the maximum. `listLists` includes subscriber counts when the provider returns them; `getList` omits counters because the single-list endpoint omits them. Embedded relationships, custom field values, activity, deals, and provider links are excluded from Flow results. The account's API Key is sent in the `Api-Token` header, never in a URL or result.

Sign in to [ActiveCampaign](https://www.activecampaign.com/login), then open Settings > Developer. Copy the full account-specific API URL into `baseUrl` and the current user's API Key into the secret `api_key` field. The API URL ends in `/api/3`; blank `baseUrl` prevents connection creation. The [contact-inspection Flow](go/examples/contact-inspection/README.md) is the runnable consumer. See the [authentication guide](https://developers.activecampaign.com/reference/authentication) and [contact API](https://developers.activecampaign.com/reference/list-all-contacts).

Go also provides contact tag definition CRUD: `listTags`, `getTag`, `createTag`, `updateTag`, and `deleteTag`. The API user needs tag management permission for writes. `createTag` is repeat-safe because ActiveCampaign returns the existing tag for the same name and type; `updateTag` sets absolute fields and `deleteTag` converges on absence. `deleteTag` removes the tag's effect from every contact and may affect automations and segments; use the contact-tag relationship operation to remove a tag from one contact. Tag names must be 1–250 characters without commas, line breaks, markup, or emoji. See the [tag API](https://developers.activecampaign.com/reference/create-a-new-tag).

Go deal operations are `listDeals`, `getDeal`, `createDeal`, `updateDeal`, and `deleteDeal`. The API user needs Deals and pipeline management permission. Create takes a primary contact, pipeline, stage, title, ISO currency, and value in minor currency units; it uses a three-send cap and reads back by title and matching fields after an unknown outcome. An ambiguous read-back selects `uncertain`. Update sets supplied absolute fields. Delete converges on absence and permanently removes the deal. Results exclude embedded contacts and links. See the [deal API](https://developers.activecampaign.com/reference/deal) and [create endpoint](https://developers.activecampaign.com/reference/create-a-deal-new).

Go deal-note operations are `listDealNotes`, `getDealNote`, `createDealNote`, and `updateDealNote`. Create uses a three-send cap and reads back exact text from the selected deal after an unknown outcome; duplicate matches select `uncertain`. Update replaces the entire note text by deal and note ID. The API user needs Deals and pipeline management permission. See the [deal note create](https://developers.activecampaign.com/reference/create-a-deal-note), [update](https://developers.activecampaign.com/reference/update-a-deal-note), and [list notes](https://developers.activecampaign.com/reference/retrieve-list-of-all-notes) contracts.

Go CRM account operations are `listAccounts`, `getAccount`, `createAccount`, `updateAccount`, and `deleteAccount`. Create uses a three-send cap and reads back by name and website after an unknown outcome; duplicate matches select `uncertain`. Update replaces selected fields and delete converges on absence. Deleting an account can affect its contact and deal relationships; select the numeric account ID deliberately. Results omit embedded relationship links. The API user needs CRM account management permission. See the [account API](https://developers.activecampaign.com/reference/list-all-accounts), [create](https://developers.activecampaign.com/reference/create-an-account-new), [update](https://developers.activecampaign.com/reference/update-an-account-new), and [delete](https://developers.activecampaign.com/reference/delete-an-account) contracts.

Go account-contact relationship operations are `listAccountContacts`, `getAccountContact`, `createAccountContact`, `updateAccountContact`, and `deleteAccountContact`. Create uses a three-send cap and reads back by contact ID after an unknown outcome; the provider allows only one account per contact, so a different existing link selects `uncertain`. Update changes the job title or moves the contact to another account, and delete removes only the link. Moving or removing a link can start account-change automations. The API user needs contact edit permission. See the [list](https://developers.activecampaign.com/reference/list-all-associations-1), [create](https://developers.activecampaign.com/reference/create-an-account-1), [update](https://developers.activecampaign.com/reference/update-an-association-1), and [delete](https://developers.activecampaign.com/reference/delete-an-association-1) contracts.

Go Deep Data ecommerce connection operations are `listConnections`, `getConnection`, `createConnection`, `updateConnection`, and `deleteConnection`. Create uses a three-send cap and reads back by the service and external store ID; ambiguous matches select `uncertain`. Update sets supplied absolute fields. Delete removes the connection and can interrupt its ecommerce synchronization, so select the numeric connection ID deliberately. Integrations created internally by ActiveCampaign can be read but cannot be changed through the API. Results omit provider links and synchronization internals. See the [connection API](https://developers.activecampaign.com/reference/connections), [create](https://developers.activecampaign.com/reference/create-connection), [update](https://developers.activecampaign.com/reference/update-connection), and [delete](https://developers.activecampaign.com/reference/delete-connection) contracts.

Go Deep Data customer operations are `listEcommerceCustomers`, `getEcommerceCustomer`, `createEcommerceCustomer`, `updateEcommerceCustomer`, and `deleteEcommerceCustomer`. Create uses a three-send cap and reads back by connection and external store ID; conflicting email matches select `uncertain`. Update replaces only the external store ID or email, and delete converges on absence. ActiveCampaign usually updates customer aggregates automatically from orders, so direct updates should be rare. These operations do not set marketing consent; results exclude revenue aggregates and provider links. See the [customer API](https://developers.activecampaign.com/reference/list-all-customers), [create](https://developers.activecampaign.com/reference/create-customer), [update](https://developers.activecampaign.com/reference/update-customer), and [delete](https://developers.activecampaign.com/reference/delete-customer) contracts.

Go order reads are `listEcommerceOrders` and `getEcommerceOrder`; line-item reads are `listEcommerceOrderProducts`, `getEcommerceOrderProduct`, and `listProductsForEcommerceOrder`. The list inputs use optional zero-based `offset` and at most 100 `limit`; the provider default applies when omitted. Order totals and line prices are returned in minor currency units. Results exclude billing and shipping addresses, provider links, and full product descriptions. Order products are read-only in the provider API and are written as part of an order. See [orders](https://developers.activecampaign.com/reference/list-all-orders), [order products](https://developers.activecampaign.com/reference/e-commerce-order-products), and the [pagination contract](https://developers.activecampaign.com/reference/pagination).

Go contact-tag relationships use `listContactTags`, `applyTagToContact`, and `removeTagFromContact`. Apply takes an existing tag ID and explicitly disables tag-definition creation; repeating it returns the existing association. Remove targets one contact and tag and converges when already absent. The API user needs contact edit permission. See the [apply tags](https://developers.activecampaign.com/reference/apply-tags-to-a-contact) and [contact tag listing](https://developers.activecampaign.com/reference/retrieve-contact-tags) contracts.

Go list subscriptions use `listContactListMemberships`, `subscribeContactToList`, and `unsubscribeContactFromList`. Both writes read the current membership before sending and use a three-send cap because changing list status can start automations, webhooks, autoresponders, or campaign sends. Subscribe explicitly resubscribes a previously unsubscribed contact when the API user has resubscribe permission; use it only with the contact's consent. Unsubscribe keeps the provider's consent-history record and converges when already unsubscribed or absent. A capped or ambiguous change selects `uncertain`. See the [subscription status contract](https://developers.activecampaign.com/reference/update-list-status-for-contact).

All operations retry transport failures, HTTP 429, request timeout, and server failures. The two writes use `repeatOnUnknown: safe`: repeating `syncContact` sets the same fields for the same email, and repeating `updateContact` sets the same fields on the same contact ID. Omitted name fields leave existing values alone; supplied empty names clear them. `getContact` and `updateContact` select `notFound` on a definitive 404. Provider rejections and malformed or oversized responses select optional branches. An unwired optional branch fails the Flow. Python and TypeScript continue to replay their declared read capabilities only. Deleting a contact is excluded because the provider also anonymizes history and can delete associated deals and tasks; a duplicate or partial deletion is hard to reverse. See the [provider upsert](https://developers.activecampaign.com/reference/sync-a-contacts-data), [update](https://developers.activecampaign.com/reference/update-contact), and [delete](https://developers.activecampaign.com/reference/delete-contact) contracts.

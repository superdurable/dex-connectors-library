# Dropbox connector

The Go connector lists a bounded folder page with `listFolder`, follows its cursor with `continueFolder`, reads one file or folder identity with `getMetadata`, downloads bounded file content with `downloadFile`, and replaces a file at an absolute path with `uploadFile`. Query results contain selected IDs, names, paths, kinds, and cursors; unselected provider fields and token material do not enter Flow results. `downloadFile` returns content as Base64. `uploadFile` accepts Base64 content and returns only file identity. A `listFolder` cursor can enumerate later pages and read later changes. `listFolder` requires `limit`; an omitted or empty `path` lists the root folder.

Create a Scoped access app in the [Dropbox Developer Console](https://www.dropbox.com/developers/apps). Choose App folder or Full Dropbox, enable `files.metadata.read`, `files.content.read`, and `files.content.write` under Permissions, and register the exact redirect URI shown by Dex Web under Settings > OAuth 2. Copy App key and App secret into the Dex authorization form, then complete user consent. Dex stores the short-lived access token and refresh token. See the [Dropbox OAuth guide](https://docs.dropboxapi.com/dropbox-api/docs/oauth), [list folder API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/list-folder), [get metadata API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/get-metadata), [download API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/download), and [upload API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/upload). Runnable consumers are the [folder-discovery Flow](go/examples/folder-discovery/README.md), [folder-continuation Flow](go/examples/folder-continuation/README.md), [file-download Flow](go/examples/file-download/README.md), and [file-upload Flow](go/examples/file-upload/README.md).

The Queries and upload Mutation retry transport failures, HTTP 429, request timeout, and server failures. Upload uses Dropbox overwrite mode with `autorename: false`, so retrying writes the same bytes to the same path. A Dropbox 409 with `path/not_found` selects the optional `notFound` branch for reads; other definitive rejections select `providerRejected`. Malformed metadata selects `invalidResponse`; a file over `maxDownloadBytes` selects `tooLarge`. An unwired optional branch fails the Flow. Live Dropbox authorization and Dex Web setup have not been exercised.

The [Python package](python/README.md) and [TypeScript package](typescript/README.md) implement all five operations, replay the Go provider scenarios, and each include a runnable metadata lookup Flow. Their versions are independent of the Go module. The file-created Trigger remains to be implemented.

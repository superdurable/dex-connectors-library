# Dropbox connector

The Go connector lists a bounded folder page with `listFolder` and reads one file or folder identity with `getMetadata`. Results contain IDs, names, display paths, entry kinds, and a continuation cursor; file content, links, and token material do not enter Flow state. A `listFolder` result with `hasMore: true` needs a future continuation operation before all entries are enumerated.

Create a Scoped access app in the [Dropbox Developer Console](https://www.dropbox.com/developers/apps). Choose App folder or Full Dropbox, enable `files.metadata.read` under Permissions, and register the exact redirect URI shown by Dex Web under Settings > OAuth 2. Copy App key and App secret into the Dex authorization form, then complete user consent. Dex stores the short-lived access token and refresh token. See the [Dropbox OAuth guide](https://docs.dropboxapi.com/dropbox-api/docs/oauth), [list folder API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/list-folder), and [get metadata API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/get-metadata). The [folder-discovery Flow](go/examples/folder-discovery/README.md) is the runnable consumer.

Both Queries retry transport failures, HTTP 429, request timeout, and server failures. A Dropbox 409 with `path/not_found` selects the optional `notFound` branch; other definitive rejections select `providerRejected`. Malformed or oversized responses select `invalidResponse`. An unwired optional branch fails the Flow. Live Dropbox authorization and Dex Web setup have not been exercised.

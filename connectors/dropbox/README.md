# Dropbox connector

Safe folder and path writes retry unlisted HTTP statuses and unusable success metadata.

The Go connector lists a bounded folder page with `listFolder`, follows its cursor with `continueFolder`, reads one file or folder identity with `getMetadata`, searches names with `searchFiles`, downloads bounded file content with `downloadFile`, replaces a file at an absolute path with `uploadFile`, creates a folder if absent with `ensureFolder`, copies or moves a file or folder with `copyPath` and `movePath`, and removes a file or folder if present with `deletePath`. Query results contain selected IDs, names, paths, kinds, and cursors; unselected provider fields and token material do not enter Flow results. `downloadFile` returns content as Base64. `uploadFile` accepts Base64 content and returns only file identity. A `listFolder` cursor can enumerate later pages and read later changes. `listFolder` requires `limit`; an omitted or empty `path` lists the root folder.

Create a Scoped access app in the [Dropbox Developer Console](https://www.dropbox.com/developers/apps). Choose App folder or Full Dropbox, enable `files.metadata.read`, `files.content.read`, and `files.content.write` under Permissions, and register the exact redirect URI shown by Dex Web under Settings > OAuth 2. Copy App key and App secret into the Dex authorization form, then complete user consent. Dex stores the short-lived access token and refresh token. See the [Dropbox OAuth guide](https://docs.dropboxapi.com/dropbox-api/docs/oauth), [list folder API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/list-folder), [get metadata API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/get-metadata), [download API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/download), and [upload API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/upload). Runnable consumers are the [folder-discovery Flow](go/examples/folder-discovery/README.md), [folder-continuation Flow](go/examples/folder-continuation/README.md), [file-download Flow](go/examples/file-download/README.md), and [file-upload Flow](go/examples/file-upload/README.md).

The Queries and upload Mutation retry transport failures, HTTP 429, request timeout, and server failures. Upload uses Dropbox overwrite mode with `autorename: false`, so retrying writes the same bytes to the same path. A Dropbox 409 with `path/not_found` selects the optional `notFound` branch for reads; other definitive rejections select `providerRejected`. Malformed metadata selects `invalidResponse` for reads; a file over `maxDownloadBytes` selects `tooLarge`. The manifest declares `uploadFile` `repeatOnUnknown: safe`: it selects `providerRejected` only for HTTP 400, 401, 403, 404, 411, 413, 414, 415, or 422, or Dropbox's documented 409 with an `error_summary`, when the fully read body describes no stored file. Any other status, an unreadable or oversized body, an echoed token, or malformed 2xx metadata repeats the overwrite, so `invalidResponse` is no longer selected for uploads. A credential failure on a later upload attempt retries, because an earlier attempt may have stored the file; malformed stored credential material is terminal like a reauthorization. An unwired optional branch fails the Flow. Live Dropbox authorization and Dex Web setup have not been exercised.

`ensureFolder` accepts a folder conflict as an existing folder, and `deletePath` accepts a missing path as already deleted; both are safe to repeat. `copyPath` and `movePath` use synchronous dispatch fences and destination read-back, with at most three possible sends. An existing destination that cannot be attributed to this call selects `uncertain`; inspect it before starting another transfer.

The [Python package](python/README.md) and [TypeScript package](typescript/README.md) implement all five operations, replay the Go provider scenarios, and each include a runnable metadata lookup Flow. Their versions are independent of the Go module. The file-created Trigger remains to be implemented.

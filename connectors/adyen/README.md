# Adyen connector

The Go, Python, and TypeScript `getPaymentLink` Query reads a Checkout payment link's ID, status, and amount currency. Go also offers `createPaymentLink` with an Adyen idempotency key, `expirePaymentLink` to force the link's status to `expired`, and `listPaymentMethods` to read available method codes and names. Shopper identities and payment details stay out of Dex Results. A completed link is useful for payment workflow inspection; the operation does not retrieve a payment by PSP reference.

## Connect

In the [Adyen Customer Area](https://ca-test.adyen.com), select your company account and open **Developers > API credentials > Payments > credential username > Server settings > Authentication > API key**. Generate and copy the secret key into Dex Web `api_key`, then save the credential. Grant its **Checkout webservice role** under Permissions. The key is sent in `X-API-Key`. See [API credentials](https://docs.adyen.com/development-resources/api-credentials/) and [roles](https://docs.adyen.com/development-resources/api-credentials/roles).

Leave `baseUrl`, `timeout`, and `maxResponseBytes` blank for their displayed defaults in test. Live requires a live API key and a URL with your company prefix from **Developers > API URLs > Prefix**: `https://{PREFIX}-checkout-live.adyenpayments.com/checkout/v72`. Find the non-secret link ID on the Payment Links page or in the create-link response and pass it as `paymentLinkId`, for example `PL50C5F751CED39G71`. See [Get a payment link](https://docs.adyen.com/api-explorer/Checkout/latest/get/paymentLinks/%28linkId%29) and the [Checkout API overview](https://docs.adyen.com/api-explorer/Checkout/latest/overview).

`expirePaymentLink` sends `PATCH /paymentLinks/{linkId}` with `status: expired`. Adyen documents `expired` as the only accepted update value, and repeating the absolute setting is safe. The operation returns only the ID, status, and currency. See [Update the status of a payment link](https://docs.adyen.com/api-explorer/Checkout/latest/patch/paymentLinks/%28linkId%29).

`createPaymentLink` sends `POST /paymentLinks` with a stable `Idempotency-Key`. In Customer Area, find `merchantAccount` under **Settings > Merchant accounts**; use the account identifier as a non-secret string. Set a unique `reference` for later payment status matching, a three-letter uppercase ISO `currencyCode`, and a positive `amountMinorUnits` using [Adyen's minor-unit table](https://docs.adyen.com/development-resources/currency-codes/). `countryCode` is an optional uppercase two-letter shopper country; blank omits it and lets Adyen determine available methods from the remaining request. The returned `url` is the shopper-facing payment page; share it only with the intended shopper. See [Create a payment link](https://docs.adyen.com/api-explorer/Checkout/latest/post/paymentLinks).

`listPaymentMethods` sends a read-only `POST /paymentMethods` for the same merchant, amount, currency, and optional country fields. It returns only `paymentMethods[].type` and `paymentMethods[].name`, discarding stored shopper methods, payment form configuration, and other provider response fields. See [Get available payment methods](https://docs.adyen.com/api-explorer/Checkout/latest/post/paymentMethods).

Go payment modification operations are `capturePayment`, `cancelPayment`, `refundPayment`, `reversePayment`, and `updateAuthorisedAmount`. Each sends `POST /payments/{paymentPspReference}/{action}` with a stable provider `Idempotency-Key`, so an unknown outcome can be retried with the same key. Find the non-secret `paymentPspReference` in **Customer Area > Payments > Payment list**, and the `merchantAccount` under **Settings > Merchant accounts**; blank required values are invalid. `reference` is an optional non-secret reconciliation ID of up to 80 characters; blank omits it. Capture, refund, and amount update require a positive `amountMinorUnits` and the original three-letter uppercase `currencyCode`; use [Adyen's minor-unit table](https://docs.adyen.com/development-resources/currency-codes/). Cancel and reverse take no amount. Capture applies to authorised payments; refund applies after capture; reversal cancels or refunds the full payment according to its state and is unsuitable for multiple partial captures. Authorisation amount update replaces the amount before capture. A `received` result means Adyen accepted the request for asynchronous processing, **not** that the money movement succeeded; inspect the corresponding CAPTURE, CANCELLATION, REFUND, CANCEL_OR_REFUND, or AUTHORISATION_ADJUSTMENT webhook for the final outcome. The result contains only payment and modification PSP references and request status, never shopper or payment details. See the [capture](https://docs.adyen.com/api-explorer/Checkout/latest/post/payments/_paymentPspReference_/captures), [cancel](https://docs.adyen.com/api-explorer/Checkout/latest/post/payments/_paymentPspReference_/cancels), [refund](https://docs.adyen.com/api-explorer/Checkout/latest/post/payments/_paymentPspReference_/refunds), [reversal](https://docs.adyen.com/api-explorer/Checkout/latest/post/payments/_paymentPspReference_/reversals), and [amount update](https://docs.adyen.com/api-explorer/Checkout/latest/post/payments/%28paymentPspReference%29/amountUpdates) contracts.

## Examples and verification

Run the [Go](go/examples/payment-link-inspection/README.md), [Python](python/examples/payment_link_inspection/README.md), or [TypeScript](typescript/examples/payment-link-inspection/README.md) Flow with the static `adyen` connection. Go-recorded conformance checks requests, branches, retries, and outputs across the three languages. Real Dex integration tests use fixture providers. Real Adyen authorization and link retrieval remain unverified.

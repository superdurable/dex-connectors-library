# Adobe Marketo Engage connector

The Go, Python, and TypeScript packages read selected lead profile fields through the Marketo REST API. `getLead` takes a positive lead ID and returns its ID, first name, and last name. Go also offers `findLeadsByEmail`, a paged exact-email search returning only IDs and names; `createLead`, which uses `createOnly` and checks for an existing email; `upsertLeadByEmail`, which uses `createOrUpdate`; and `updateLead`, an absolute replacement of selected names on an existing ID. Email is sent to Marketo but omitted from all results. `updateLead` uses `action: updateOnly` and `lookupField: id`, so repeating an unknown outcome cannot create a second lead. Empty updates and invalid IDs select `defect`; a missing lead selects `notFound`. Rate limits, transient failures, and expired tokens ask Dex to retry. Python and TypeScript retain their original `getLead` capability and version.

`createLead` uses the `limited` repeat tier with three possibly effective sends, reads matching leads back before a resend, and selects `uncertain` if an earlier write cannot be confirmed. A first-attempt Marketo 1005 selects `alreadyExists`. `upsertLeadByEmail` is `safe` because its repeated input selects the same email and replaces the same names, although Marketo warns that concurrent upserts with the same key may create duplicates; callers should serialize distinct Flows for one email when that matters. Neither operation returns the email or provider-supplied error text.

Go also provides `getActivityPagingToken`, `listActivityTypes`, and `listActivities`. Start with a timezone-qualified RFC 3339 timestamp, select one to ten activity type IDs, and pass the returned cursor through each activity page. Activity results contain only IDs, dates, and type IDs; Marketo form fields, IP addresses, URLs, and primary attribute values are discarded. These read operations are safe to retry. Marketo can take up to 300 seconds to respond to its paging-token endpoint, while the connector's Execute timeout is 30 seconds; a slow token request will retry, so provider latency beyond that limit remains unverified. [Adobe's activity guide](https://experienceleague.adobe.com/en/docs/marketo-developer/marketo/rest/lead-database/activities) describes cursor paging and activity retention.

Go company operations use the source system's unique `externalCompanyId`: `getCompanyByExternalID` reads only the provider ID and company name; `createCompany` uses `createOnly`, bounded sends, and read-back; `upsertCompany` replaces the name by the same key; and `deleteCompany` treats an already absent record as deleted. Create is `limited` with three possible sends, while read, upsert, and delete are `safe`. Marketo's company endpoints are read-only when Salesforce or Microsoft Dynamics synchronization owns company data. See [Adobe's company guide](https://experienceleague.adobe.com/en/docs/marketo-developer/marketo/rest/lead-database/companies).

## Connection

In Dex Web **Connections**, create `adobe-marketo` using the authorization guide in `connector.yaml`. In Marketo, create an API-Only user with an API role granting Access API > Read-Only Lead, Read-Only Activity for activity queries, Read-Only Company for company reads, and Read-Write Company for company writes, and, when using `createLead`, `upsertLeadByEmail`, or `updateLead`, Read-Write Lead. Then create a Custom service in Admin > Integration > LaunchPoint. Enter its Client ID and secret into Dex Web. Under Admin > Integration > Web Services, copy the subscription REST Endpoint into `restEndpoint` and the Identity URL into `tokenEndpoint` with `/oauth/token` appended. Both URLs must use the same HTTPS `.mktorest.com` host. Leave `access_token`, `timeout`, and `maxResponseBytes` blank. Dex mints and refreshes the access token using the custom service.

The [runnable Go](go/examples/lead-inspection/README.md), [Python](python/examples/lead_inspection/README.md), and [TypeScript](typescript/examples/lead-inspection/README.md) Flows use this static connection name. Optional branches are unwired and fail the Flow when selected. The real Marketo authorization form and provider read have not been verified live.

This operation follows Adobe's [Lead API](https://experienceleague.adobe.com/en/docs/marketo-developer/marketo/rest/lead-database/leads), [authentication](https://experienceleague.adobe.com/en/docs/marketo-developer/marketo/rest/authentication), and [error code](https://experienceleague.adobe.com/en/docs/marketo-developer/marketo/rest/error-codes) contracts.

# Elasticsearch connector

The Go package provides `getDocument`, `searchDocuments`, `indexDocument`, `createDocument`, `updateDocument`, and `deleteDocument` for one concrete index, plus `createIndex`, `deleteIndex`, `getIndex`, and `listIndices` for index management. Python and TypeScript retain the three original operations. `getDocument` reads a complete source by stable ID through [Elasticsearch's Get API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-get). Search returns total-hit information and each hit's ID, score, and source JSON. Indexing fully replaces one document under a caller-supplied stable ID; deletion ensures that ID is absent. Use an existing index without nonrepeatable ingest pipeline effects for index retries. Document source is untrusted provider data; restrict index permissions and avoid placing credentials in documents that a Flow can read.

Set `clusterUrl` to the HTTPS Direct endpoint at https://cloud.elastic.co/ > deployment > Manage > Application endpoints > Elasticsearch, or a self-managed cluster HTTP endpoint. In Kibana, create a native user under **Stack Management > Security > Users** and a role under **Stack Management > Security > Roles** with `read`, `index`, or `delete` for document operations; add `view_index_metadata`, `create_index`, or `delete_index` for the corresponding index operations. Assign the role while creating the user, then save its username and secret password in Dex Connections. This initial Basic-auth connector targets Elastic Stack deployments, not Elastic Cloud Serverless. See [Elasticsearch security permissions](https://www.elastic.co/docs/deploy-manage/users-roles/cluster-or-deployment-auth/kibana-role-management).

`getDocument` selects `found`, `notFound`, `providerRejected`, `invalidResponse`, or `defect`; rate limits, server errors, and transport failures retry. `searchDocuments` selects `found`, `indexNotFound`, `providerRejected`, `invalidResponse`, or `defect`. HTTP 429, 503, other server errors, transport failures, timed-out searches, and shard failures retry under the default one-hour policy. The connector requests `allow_partial_search_results=false`. `indexDocument` selects `indexed`, `providerRejected`, or `defect`; `deleteDocument` selects `absent`, `indexNotFound`, `providerRejected`, or `defect`. Their fixed-ID writes are safe to repeat. The connector retries transport, rate-limit, server, and unconfirmed response failures until its retry budget ends. A repeated deletion that finds no document completes through `absent` with `wasDeleted: false`. Writes use Elasticsearch's default refresh timing, so an immediate search may briefly see the prior state. Runnable examples cover [read and search](go/examples/document-search/README.md), [replacement](go/examples/document-index/README.md), and [deletion](go/examples/document-delete/README.md).

The [Python](python/README.md) and [TypeScript](typescript/README.md) packages replay their three declared operations from the [Go-recorded provider scenarios](../../../conformance/connectors/elastic/elasticsearch/scenarios.json). Live Elastic authorization remains unverified.

`updateDocument` uses the [Elasticsearch Update API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-update) with a `doc` object of absolute field values. It merges into an existing document without scripts or increments; `updated` includes a provider `noop`, and a missing document selects `notFound`. Repeating the same field values is safe. Grant the role `write` or `index` on the target index. The [document update example](go/examples/document-index/README.md) uses this Go-only operation.

`createDocument` sends `POST /{index}/_doc` so Elasticsearch generates the ID. It is a Go-only limited mutation: a durable dispatch fence bounds possible sends to three, rate limits and 503 responses permit resend, and an unconfirmed outcome at the cap selects `uncertain`. When a response provides an ID, retry reads it back before another send. If the response is lost before the ID is known, duplicate documents remain possible within the cap; applications should use `indexDocument` with a stable ID when they can choose one. Grant `create_doc` or `write` for this operation and avoid nonrepeatable ingest pipeline effects. The [document creation example](go/examples/document-index/README.md) exercises it.

Index operations use the [create](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-indices-create), [delete](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-indices-delete), and [get](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-indices-get) APIs. `createIndex` ensures an index exists with provider defaults; `deleteIndex` ensures it is absent and removes all of its documents. Both retry unknown results safely and accept the corresponding already-present or already-absent response. `getIndex` and `listIndices` return bounded provider metadata, including settings, mappings, and aliases. Listing uses `GET /*` with non-hidden indices because Elastic recommends index APIs for applications over CAT APIs; the configured `maxResponseBytes` bounds the full response. Grant these privileges only on intended index patterns. The [index read example](go/examples/document-search/README.md) exercises `getIndex`.

# Keap connector

The Go, Python, and TypeScript `getContact` Query reads one Keap CRM v2 contact by ID. Go also provides `listContacts`, `upsertContact`, and `deleteContact`. These use the [Keap CRM v2 contact API](https://developer.keap.com/docs/api/keap). The returned profiles contain only IDs and names. HTTP 404 selects the optional `notFound` branch on ID lookup and deletion. Rate limits, server failures, and transport failures retry.

`listContacts` takes a page size of 1–100 and an opaque continuation token; zero size uses 20 and blank token starts the first page. `upsertContact` uses Keap's `duplicate_option=Email` to update the matching email or create a contact, so repeating the same request is safe. Provide a valid email (at most 75 characters) and bounded names. `deleteContact` removes the selected ID. The Go operations use safe repeat semantics.

Go also provides `getCompany`, `listCompanies`, `createCompany`, `updateCompany`, and `deleteCompany` against the [Keap company API](https://developer.keap.com/docs/api/keap). The list accepts a page size of 1–100 (zero uses 20) and an opaque page token. In Keap CRM, open **Companies** and select a company to find its ID. Company IDs are 1–128 ASCII letters, digits, hyphens, or underscores; blank is invalid. A company name is required for create or update and must be at most 256 bytes. The create operation uses a limited three-send budget because Keap does not advertise a company-create idempotency key. If the outcome cannot be confirmed after that budget, it selects `uncertain`; reconcile the Companies page before attempting another create. Lookups, lists, name replacement, and deletion use safe repeat semantics. A blank page token starts the first page, and a missing company selects `notFound` for ID operations.

Go also provides `getContactNote`, `listContactNotes`, `createContactNote`, `updateContactNote`, and `deleteContactNote` through the [Keap note API](https://developer.keap.com/docs/api/keap). In Keap CRM, open **Contacts**, choose a contact, then its **Notes** section to find the contact and note IDs. Both IDs use the same 1–128-character format as contact IDs; blank is invalid. The list accepts a page size of 1–100 (zero uses 20) and an opaque page token; blank starts the first page. To create a note, choose its author in **Admin settings > Users** and supply that user's Keap ID as `userId`; the [Keap create-note request](https://github.com/infusionsoft/keap-sdk-php/blob/main/docs/Model/CreateNoteRequest.md) requires it. A title of at most 256 bytes is required; body text may be blank and is limited to 16,384 bytes. Updating a note replaces both title and body, so blank body clears it. The create uses a limited three-send budget and may select `uncertain`; inspect the contact's Notes before another create. Other note operations are safe to repeat. Keap user-ID discovery and live note responses have not been verified with a real account.

Go also provides `listContactTags`, `applyContactTag`, and `removeContactTag` through the [Keap tag API](https://github.com/infusionsoft/keap-sdk-php/blob/main/docs/Api/TagsApi.md). In Keap CRM, open **Contacts**, select a contact, and inspect **Tags**; create or find a tag under **Settings > Tags**. Use the contact and tag IDs from their records, each in the same 1–128-character ID format; blank is invalid. Listing uses a page size of 1–100 (zero uses 20) and an opaque page token, with blank starting the first page. Applying a tag to a contact that already has it and removing an absent tag target the same final state, so these actions use safe repeat semantics. Provider permission and exact live action responses remain unverified.

## Connection and configuration

For your own account, open Keap **API Settings > Personal Access Tokens**, generate a Personal Access Token, and copy its complete value into the secret `personalAccessToken` field in Dex Web Connections. The [Keap getting-started guide](https://developer.keap.com/docs/getting-started) confirms that a Personal Access Token is for calling the API as yourself; third-party apps acting for other users require OAuth 2.0. This connector's connection method does not perform OAuth. Blank token is invalid. Treat the token as a password and rotate it in Keap when needed.

Leave `baseUrl` blank for the production CRM root. Override it only for a trusted test gateway; do not append `/rest/v2/contacts`. Leave `timeout` and `maxResponseBytes` blank for their displayed defaults. In Keap CRM, open **Contacts**, select the contact, and copy its ID. Pass it as `contactId`; blank is invalid. For upsert, use that contact's email or a new email you intend to add. The official [Keap v2 contact API](https://developer.keap.com/docs/api/keap) documents the list, upsert, and deletion paths.

Runnable examples are in [`go/examples/contact-read`](go/examples/contact-read), [`python/examples/contact_read`](python/examples/contact_read), and [`typescript/examples/contact-read`](typescript/examples/contact-read). The Go example also registers a contact-directory Flow. Provider conformance scenarios are recorded from Go; Python and TypeScript replay only their published `getContact` capability. Live Keap authorization and provider behavior require a user-controlled token and remain unverified here.

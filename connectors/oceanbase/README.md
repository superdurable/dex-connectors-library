# OceanBase Cloud connector

This connector reads one page of cluster instances in an OceanBase Cloud project using the official [DescribeInstances Open API](https://docs.oceanbase.com/oceanbase-cloud/describe-instances-of-api). It sends `GET /api/v2/instances` with a generated request ID, page parameters, and `X-Ob-Project-Id`. It returns only cluster IDs, names, state, region, and the total count. No personal data or AccessKey material enters outputs, receipts, Attributes, or failures.

OceanBase Cloud uses HTTP Digest with an AccessKey ID and Secret. In the [OceanBase Cloud console](https://cloud.oceanbase.com/), open **AccessKey → Create AccessKey** and copy both values. Open **Projects → target project → Configure Project → Project settings → Project information** to find Project ID. Select the service site where the instance was ordered; the connector uses OceanBase's fixed [domestic or international HTTPS endpoint](https://docs.oceanbase.com/oceanbase-cloud/service-endpoints). Redirects are disabled, and Digest retries only one challenge. AccessKeys have full privileges on the account, so protect them and rotate them in the console when needed.

The runnable [instance-list Flow](go/examples/instance-list/README.md) uses a static `oceanbase` connection and generated operation-specific Step. Transient HTTP/transport failures retry under Dex's default one-hour retry budget. Definite provider rejections select the optional `providerRejected` branch. Live AccessKey authorization and real instance responses remain unverified without a user-controlled OceanBase Cloud connection.

# Lucid connector

The Go `listDocuments` Query calls Lucid REST API v1 `POST /documents/search` with `excludeTrashed: true`. Although the endpoint uses POST, it only searches documents. The connector returns one page of document IDs and titles plus an opaque next-page token from Lucid's `Link` header. `pageToken` is optional: omit it or leave it blank to read the first page. Go also provides `getDocument`, a safe Query for one document's ID, title, product, version, page count, and edit permission. Both operations exclude document content, owners, URLs, and custom attributes. HTTP 429, 408, 5xx, and transport failures retry.

Create a personal API key in the [Lucid Developer Portal > API Keys](https://lucid.app/developer) with the `DocumentReadonly` grant. Enter it in Dex Web's secret `api_key` field. This grant permits searching and reading documents but not creating, updating, trashing, or copying them; those mutations need `DocumentEdit` and would change the existing connection contract. Folder operations need a separate `FolderReadonly` or `FolderEdit` grant. This is intended for personal or internal use; Lucid recommends OAuth clients for published apps. See [Search Documents](https://developer.lucid.co/reference/searchdocuments), [Get Document](https://developer.lucid.co/reference/getorexportdocument), [API Key Grants](https://developer.lucid.co/reference/api-key-grants), and [pagination](https://developer.lucid.co/reference/reference-rest#pagination).

The runnable Dex Flows are in [`go/examples/document-discovery`](go/examples/document-discovery/README.md). Their static connection name is `lucid`. The Go connector declares `v0.3.0`; Python and TypeScript remain `v0.2.0` and replay their declared Go-recorded scenarios. Live Lucid authorization and provider reads were not verified in this checkout.

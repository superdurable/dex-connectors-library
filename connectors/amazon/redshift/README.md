# Amazon Redshift connector

Go operations use AWS Signature Version 4 with service `redshift-data`:

| Operation | API | Result | Repeat tier |
| --- | --- | --- | --- |
| `executeStatement` | [ExecuteStatement](https://docs.aws.amazon.com/redshift-data/latest/APIReference/API_ExecuteStatement.html) | Statement UUID | safe with `ClientToken` |
| `describeStatement` | [DescribeStatement](https://docs.aws.amazon.com/redshift-data/latest/APIReference/API_DescribeStatement.html) | Status and result availability, without SQL text | safe |
| `listStatements` | [ListStatements](https://docs.aws.amazon.com/redshift-data/latest/APIReference/API_ListStatements.html) | One page of IDs and statuses, without SQL text | safe |
| `cancelStatement` | [CancelStatement](https://docs.aws.amazon.com/redshift-data/latest/APIReference/API_CancelStatement.html) | Cancellation accepted or optional `notCanceled` | safe |
| `getStatementResult` | [GetStatementResult](https://docs.aws.amazon.com/redshift-data/latest/APIReference/API_GetStatementResult.html) | One cached JSON result page | safe |

`executeStatement` takes a Serverless workgroup name, database name, and one SQL statement up to 200 KiB. It sends the Dex call identity as `ClientToken`. [AWS retains this deduplication token for up to eight hours](https://docs.aws.amazon.com/redshift/latest/mgmt/data-api.html); do not resume an uncertain execution after that window without checking statement history. Do not put credentials or secrets in SQL or Flow inputs. The submission branch means Redshift accepted the statement, not that SQL completed; use `describeStatement` to check status. `cancelStatement` reads back status when a cancellation response says it was not accepted; an already aborted statement counts as canceled. `listStatements` accepts `maxResults` up to 100 and a previous `nextToken`; blank token starts at the first page.

`getStatementResult` takes `statementId` and an earlier page's `nextToken` (blank for the first page). The `fetched` branch returns `records` as arrays of Redshift Field objects, `totalNumRows`, and `nextToken`; continue until the token is blank. Optional `missing` branches handle statements Redshift no longer retains. Throttling, 429, 408, 5xx, and transport errors retry. Definitive rejection, malformed responses, and invalid input take optional branches.

In the [Redshift Query Editor v2](https://console.aws.amazon.com/redshiftv2), select the Region, find the workgroup under **Serverless > Workgroups**, and find the database in the connection selector. Copy a statement `Id` to Flow input for describe, cancel, or result retrieval. In the [IAM Console](https://console.aws.amazon.com/iam), open **Users > selected user > Security credentials > Access keys > Create access key**. Grant only the `redshift-data` actions used by the Flow and `redshift-serverless:GetCredentials` on the chosen workgroup for submission; consider the [statement owner IAM condition](https://docs.aws.amazon.com/redshift/latest/mgmt/data-api-iam.html) to restrict result access. Enter the access key ID and one-time secret in Dex secret fields; temporary credentials also need their STS session token. Leave `endpoint` blank for the regional AWS API and leave `timeout` and `maxResponseBytes` blank for displayed defaults.

The [Go](go/examples/statement-results/README.md), [Python](python/examples/statement_results/README.md), and [TypeScript](typescript/examples/statement-results/README.md) examples run typed Flows. Go includes the new operations; Python and TypeScript retain `getStatementResult`. [Go-recorded conformance scenarios](../../../conformance/connectors/amazon/redshift/scenarios.json) cover branches, throttling, server errors, transport failure, and invalid input. Provider fixtures and real Dex Worker tests are included. Live AWS authorization and calls have not been verified.

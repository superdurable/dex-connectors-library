# OpenSearch connector

The Go, Python, and TypeScript connectors provide `searchDocuments`, `indexDocument`, and `deleteDocument` for one concrete index. Search returns total-hit information and each hit's ID, score, and source JSON. Indexing fully replaces one document under a caller-supplied stable ID; deletion ensures that ID is absent. Use an existing index without nonrepeatable ingest pipeline effects for index retries. Search source is untrusted provider data; restrict index permissions and avoid placing credentials in documents that a Flow can read.

Set `clusterUrl` to the HTTPS REST endpoint from your OpenSearch deployment or managed-service console. In OpenSearch Dashboards, create an internal user under **Security > Internal users** and a role under **Security > Roles** with `indices:data/read/search`, `indices:data/write/index`, or `indices:data/write/delete` for the intended index pattern, according to the operations used. Map the user to the role, then save its username and secret password in Dex Connections. See [OpenSearch security permissions](https://docs.opensearch.org/latest/security/access-control/permissions/).

`searchDocuments` selects `found`, `indexNotFound`, `providerRejected`, `invalidResponse`, or `defect`. HTTP 429, 503, other server errors, transport failures, timed-out searches, and shard failures retry under the default one-hour policy. The connector requests `allow_partial_search_results=false`. `indexDocument` selects `indexed`, `providerRejected`, or `defect`; `deleteDocument` selects `absent`, `indexNotFound`, `providerRejected`, or `defect`. Their fixed-ID writes are safe to repeat, so both declare `repeatOnUnknown: safe`. A write selects `providerRejected` only for HTTP 400, 401, 403, 404, 411, 413, 414, 415, or 422; the connector retries every other status, transport, rate-limit, server, and unconfirmed response failure until its retry budget ends. Every operation selects `defect` for a credential failure only when reauthorization is required, the connection is missing or not selected, the credential broker refused, or the credential fails a local check; any other credential failure, such as an unavailable credential broker, retries. A repeated deletion that finds no document completes through `absent` with `wasDeleted: false`. Writes use OpenSearch's default refresh timing, so an immediate search may briefly see the prior state. Runnable examples cover [search](go/examples/document-search/README.md), [replacement](go/examples/document-index/README.md), and [deletion](go/examples/document-delete/README.md).

The Python and TypeScript packages replay the [Go-recorded provider scenarios](../../conformance/connectors/opensearch/scenarios.json) and include runnable [Python](python/README.md) and [TypeScript](typescript/README.md) Flows.

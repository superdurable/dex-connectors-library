# Braze connector

The Go connector supports `getUserProfile`, `updateUserProfile`, `deleteUserProfile`, `listCampaigns`, `listCanvases`, `listSegments`, `triggerCampaignSend`, and `triggerCanvasSend`. The profile lookup calls `POST /users/export/ids` for one external user ID and returns only `external_id`, `braze_id`, `first_name`, `last_name`, and `email`. An empty `users` array selects `notFound`.

`updateUserProfile` calls `POST /users/track` with only absolute `first_name`, `last_name`, and `email` attributes. It never sends events, purchases, or custom attributes. Braze queues processing asynchronously; `accepted` confirms queueing, not final application. `deleteUserProfile` calls `POST /users/delete` for one external ID; deletion is permanent and its `deleted` count describes profiles queued for deletion. Both operations are safe to retry with the same absolute update or deletion target. The three list Queries return one zero-based page of up to 100 identities. The segment list includes the analytics tracking setting.

`triggerCampaignSend` and `triggerCanvasSend` target one existing external user ID in a dashboard-configured API-triggered campaign or Canvas. They never broadcast to a segment. Both use a bounded three-send policy; an unknown outcome after the cap selects `uncertain`, because Braze does not expose a dispatch ID until it acknowledges the send. The returned dispatch ID confirms acceptance, while actual delivery still depends on the dashboard audience and channel eligibility settings.

Create a REST API key in Braze Dashboard > Settings > APIs and Identifiers > API Keys with the permissions for the operations you use: `users.export.ids`, `users.track`, `users.delete`, `campaigns.list`, `canvas.list`, `segments.list`, and, for targeted sends, `campaigns.trigger.send` or `canvas.trigger.send`. Enter the account's REST Endpoint in `baseUrl` and the key in the secret `rest_api_key` field. See the [Braze API basics](https://www.braze.com/docs/api/basics), [campaign send](https://www.braze.com/docs/api/endpoints/messaging/send_messages/post_send_triggered_campaigns), [Canvas send](https://www.braze.com/docs/api/endpoints/messaging/send_messages/post_send_triggered_canvases), [user track](https://www.braze.com/docs/api/endpoints/user_data/post_user_track), [user delete](https://www.braze.com/docs/api/endpoints/user_data/post_user_delete), [campaign list](https://www.braze.com/docs/api/endpoints/export/campaigns/get_campaigns), [Canvas list](https://www.braze.com/docs/api/endpoints/export/canvas/get_canvases), and [segment list](https://www.braze.com/docs/api/endpoints/export/segments/get_segment) references.

The runnable Dex Flow is in [`go/examples/profile-inspection`](go/examples/profile-inspection/README.md). It lists campaigns before reading a profile and optionally triggers a campaign or Canvas for that user, using the static connection name `braze`. Go declares `v0.2.0`; Python and TypeScript remain at `v0.1.0` and implement only `getUserProfile`. Their conformance runners replay only that declared capability.

# SF Express route query

`QueryRoutes` reads standard delivery events for one waybill owned by the configured SF Express application. It calls `POST https://bspgw.sf-express.com/std/service` with service code `EXP_RECE_SEARCH_ROUTES`. It sends `partnerID`, a UUID, a Unix timestamp, a JSON `msgData` value, and the provider's MD5/Base64 `msgDigest` signature. The checkword stays in the protected connection and is never placed in a URL or result. The output contains only event times and codes, omitting free-text remarks, locations, and contacts.

The [official route contract](https://qiao.sf-express.com/doc/download/%E4%B8%B0%E6%A1%A5%E5%B9%B3%E5%8F%B0%E6%96%B0API%E6%8E%A5%E5%8F%A3%E8%A7%84%E8%8C%83.pdf) defines the request and nested route response. The [official Python SDK guide](https://qiao.sf-express.com/doc/download/SF-CSIM-EXPRESS-SDK-PYTHON%E6%8C%87%E5%8D%97V2.0.pdf) specifies URL encoding the concatenated message, timestamp, and checkword before MD5 and Base64. The [current platform guide](https://open.sf-express.com/developSupport/976720?authId=0%EF%BC%89) requires HTTPS form POST. The API requires the route service to be associated with the customer code. A standard query normally returns only waybills owned by that code.

HTTP 429 and 5xx, transport failures, and documented temporary platform errors retry. A definite permission or waybill rejection takes the optional `providerRejected` branch, which fails an example Flow unless deliberately wired. The response is limited to 1 MiB and 100 events by default.

The [runnable Dex Flow](go/examples/route-query/README.md) demonstrates a static connection, typed input, durable result, strict FDG, and a mock backed by a real Dex Worker and Client. Live customer-code authorization, the production endpoint, and real route responses remain unverified.

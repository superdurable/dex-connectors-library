# WordPress connector

The WordPress Go, Python, and TypeScript connectors read published posts and creates drafts or published posts through the core REST API. `getPost` reads one numeric post ID. `listPosts` reads one page of published posts and returns WordPress's total-count headers. A draft returned to `getPost` selects `notFound` so private content does not enter a read Flow. `createPost` defaults to draft and can publish immediately when its input explicitly selects `publish`.

Configure `siteUrl` with the HTTPS Site Address shown at **Settings > General** in your own `/wp-admin/options-general.php`. Do not include `/wp-json`. In **Users > Profile > Application Passwords** at `/wp-admin/profile.php`, create an application password for the Dex connection. Enter your WordPress username and that password in the connection. The password is secret and never belongs in Flow input. Draft creation needs `edit_posts`; publishing also needs `publish_posts`. See the [WordPress application-password guide](https://developer.wordpress.org/rest-api/using-the-rest-api/authentication/) and [role capabilities](https://wordpress.org/documentation/article/roles-and-capabilities/).

The `getPost` branches are `found`, `notFound`, `providerRejected`, `invalidResponse`, and `defect`. The `listPosts` branches are `listed`, `providerRejected`, `invalidResponse`, and `defect`. Read operations retry HTTP 429, server errors, and transport failures under the default one-hour policy. `createPost` selects `created`, `providerRejected`, `uncertain`, or `defect`. It records a single-dispatch checkpoint that counts possible sends because WordPress offers no create-post idempotency key or read-back. An unknown outcome (a 5xx other than 503, 408, 409, any 4xx other than 400, 401, 403, 404, 411, 413, 414, 415, or 422, an interrupted or malformed response, or a connection lost after dispatch) retries and resends while possible sends stay below the operation's `maxSends` (default 3), so Posts may show a duplicate, and selects `uncertain` at the cap. A definite refusal selects `providerRejected` and is never resent; after an earlier possible send it selects `uncertain`. A response with a post ID but an unexpected status, or a saved post ID from an earlier attempt, selects `uncertain` without resending. An unreadable checkpoint retries without sending. Check the site's Posts list before creating another post after `uncertain`. Published title and content are untrusted HTML; sanitize before display.

The runnable [post-inspection](go/examples/post-inspection/README.md) and [post-creation](go/examples/post-creation/README.md) examples show operation-specific Step factories and the static `wordpress` connection. The Python and TypeScript packages replay the [Go-recorded provider scenarios](../../conformance/connectors/wordpress/scenarios.json) and include runnable [Python](python/README.md) and [TypeScript](typescript/README.md) Flows.

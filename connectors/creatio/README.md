# Creatio connector

The Go, [Python](python/README.md), and [TypeScript](typescript/README.md) packages implement `getContact` through [Creatio OData 4](https://academy.creatio.com/guides/dev/development-on-creatio-platform/integrations-and-api/data-services/odata/basics/overview). The Query accepts a Contact UUID and returns its ID, name, and optional email. An empty result selects `notFound`; 429, 408, 5xx, and transport failures retry. Malformed OData and definitive rejections select separate optional branches.

In your Creatio instance, open System Designer > OAuth 2.0 integrated applications > New and create a dedicated technical user with Contact read permission. Copy Client Id and Client secret into Dex Web. Find **Authorization server Url for OAuth 2.0 integrations** (`OAuth20IdentityServerUrl`) in System settings, append `/connect/token`, and enter it as `tokenEndpoint`. Enter the application root as `baseUrl`. Dex uses the [client credentials grant](https://academy.creatio.com/guides/dev/development-on-creatio-platform/integrations-and-api/authentication/oauth-2-0-authorization/identity-service-overview) and renews the access token. No redirect URI or user consent is needed.

The [Go](go/examples/contact-inspection/README.md), [Python](python/examples/contact_inspection/README.md), and [TypeScript](typescript/examples/contact-inspection/README.md) examples use the static `creatio` connection. [Go-recorded conformance scenarios](../../conformance/connectors/creatio/scenarios.json) cover provider branches and retries. Live Creatio authorization and Contact retrieval have not been verified in this checkout.

# Creatio connector

The Go, [Python](python/README.md), and [TypeScript](typescript/README.md) packages implement `getContact` through [Creatio OData 4](https://academy.creatio.com/guides/dev/development-on-creatio-platform/integrations-and-api/data-services/odata/basics/overview). Go also implements `listContacts`, `createContact`, `updateContact`, and `deleteContact`. The list Query pages through IDs, names, and emails. Create uses a durable dispatch fence with a three-send limit and reads by name and email before resending; an unproven matching contact selects `uncertain`. Update uses OData PATCH for only the supplied fields; delete removes a contact permanently. Each write requires the technical user's corresponding object permission. An empty Get result selects `notFound`; 429, 408, 5xx, and transport failures retry. Malformed OData and definitive rejections select separate optional branches.

Go also implements `getAccount`, `listAccounts`, `createAccount`, `updateAccount`, and `deleteAccount` through the OData [Account collection](https://academy.creatio.com/guides/dev/development-on-creatio-platform/integrations-and-api/data-services/odata/basics/overview). Account names are not unique. Create reads by name before resending but treats an unproven match as `uncertain`; a saved provider ID can confirm the record. Updates replace the name, and deletion is permanent. The technical user needs matching Account object permissions.

Go also implements `getActivity`, `listActivities`, `createActivity`, `updateActivity`, and `deleteActivity` through the OData Activity collection. Create requires a title and RFC3339 start and due times, with due after start. Update patches only supplied title or schedule fields; delete is permanent. Create uses a bounded three-send fence and treats an unproven title match after an unknown write as `uncertain`. The technical user needs Activity object read, create, update, and delete permission. Creatio documents Activity [Title, Start, and Due](https://academy.creatio.com/docs/user/crm_tools/activities/create_an_activity/create_activity) fields.

Go also implements `getOpportunity`, `listOpportunities`, `createOpportunity`, `updateOpportunity`, and `deleteOpportunity` through the OData Opportunity collection. Create requires a deal name and buyer contact, buyer account, and owner UUIDs; the [Creatio opportunity guide](https://academy.creatio.com/guides/creatio-apps/8.3/products/sales-tools/lead-and-opportunity-management/opportunities/create-an-opportunity) identifies these required fields. Update patches only supplied fields; delete is permanent. Create uses a bounded three-send fence and selects `uncertain` when a prior unknown write cannot be tied to its provider ID. The technical user needs Opportunity object permissions.

In your Creatio instance, open System Designer > OAuth 2.0 integrated applications > New and create a dedicated technical user with Contact, Account, Activity, and Opportunity read, create, update, and delete permission. Copy Client Id and Client secret into Dex Web. Find **Authorization server Url for OAuth 2.0 integrations** (`OAuth20IdentityServerUrl`) in System settings, append `/connect/token`, and enter it as `tokenEndpoint`. Enter the application root as `baseUrl`. Dex uses the [client credentials grant](https://academy.creatio.com/guides/dev/development-on-creatio-platform/integrations-and-api/authentication/oauth-2-0-authorization/identity-service-overview) and renews the access token. No redirect URI or user consent is needed.

The [Go](go/examples/contact-inspection/README.md), [Python](python/examples/contact_inspection/README.md), and [TypeScript](typescript/examples/contact-inspection/README.md) examples use the static `creatio` connection. [Go-recorded conformance scenarios](../../conformance/connectors/creatio/scenarios.json) cover provider branches and retries. Live Creatio authorization and Contact retrieval have not been verified in this checkout.

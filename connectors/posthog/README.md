# PostHog connector

The Go connector captures events, aliases, person updates, page views, and screen views through PostHog's public capture API; it lists saved insight identities through the private API. `captureEvent`, `createAlias`, `identifyPerson`, `trackPageView`, and `trackScreenView` send the project token only in the request body and derive a stable UUID from the Dex call ID; timestamps and distinct IDs stay fixed across retries. PostHog deduplicates matching UUID, event, timestamp, and distinct ID eventually, so downstream live destinations may briefly receive duplicates. An HTTP acknowledgment means accepted for processing, not verified ingestion. A response naming `quota_limited` selects its own branch rather than success.

Create or copy the project token under PostHog **Settings > Project > Project variables**. To use `listInsights`, create a personal API key under **avatar > Account settings > Personal API Keys**, granting `insight:read` scope. Save both in Dex Connections as secrets; leave `personal_api_key` blank if the Flow only captures events. For EU Cloud set the capture and app hosts to `https://eu.i.posthog.com` and `https://eu.posthog.com`. Self-hosted users set both to their HTTPS origin. The [PostHog API overview](https://posthog.com/docs/api) describes these separate hosts and credentials.

`listInsights` accepts a positive project ID from the PostHog project URL or project settings and returns a bounded page of insight IDs and names, without query results or private metadata. Its `offset` and `limit` are optional: an omitted or zero offset starts at the first insight, and an omitted or zero limit reads 20. Both operations retry rate limits, server errors, and transport failures. A malformed or oversized capture confirmation also retries with the same UUID; `captureEvent` has no terminal `invalidResponse` branch because that outcome cannot establish whether PostHog accepted the event. The [Go-recorded conformance scenarios](../../conformance/connectors/posthog/scenarios.json) cover both Python and TypeScript ports. Runnable examples for both operations are available in [Go](go/examples/event-capture/README.md), [Python](python/README.md), and [TypeScript](typescript/examples/provider-operations/README.md).

The new Go capture operations use the same project token as `captureEvent`. `createAlias` sends `$create_alias` with an existing distinct ID and a different alias. `identifyPerson` sends `$identify` with non-secret string properties under `$set`. `trackPageView` sends `$pageview` with `$current_url`; its URL must be HTTPS without credentials, query, or fragment so it cannot carry query tokens in a Flow input. `trackScreenView` sends `$screen` with `$screen_name`. Each requires a fixed RFC3339 timestamp and retries rate limits, server errors, and uncertain confirmations with the same UUID. The [Go identity example](go/examples/event-capture/README.md) runs `identifyPerson` on a separate Flow. Private API create, update, and delete operations need broader personal API key scopes than this connector's documented `insight:read` key.

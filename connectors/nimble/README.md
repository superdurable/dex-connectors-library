# Nimble CRM connector

The Go, Python, and TypeScript connectors read a page of contact IDs with `listContactIDs` and one contact's basic name and email fields with `getContact`. Go also provides `searchContactIDs`, `createContact`, `updateContact`, `deleteContact`, and the five contact note operations for listing, reading, creating, updating, and deleting notes. `listContactIDs` and `searchContactIDs` take a one-based `page` and `perPage` from 1 through 100. `getContact`, `updateContact`, and `deleteContact` take the 24-character hexadecimal ID returned by Nimble. Custom fields and links remain outside read Flow results.

`createContact` creates a person with a first or last name and optional email. It uses a three-send limited retry cap and selects `uncertain` when creation cannot be confirmed. Matching name and email cannot prove which request created a contact. `updateContact` is an absolute replacement: `Fields` must contain the complete field collection, because Nimble removes omitted fields with `type=1`. `deleteContact` uses regular deletion and does not force removal of contacts with protected relations. Updates and deletion are safe to repeat; every non-success branch is optional and fails the Flow when unwired.

`listContactNotes` and `getContactNote` are safe reads. `createContactNote` is a limited write with a three-send cap and selects `uncertain` when creation cannot be confirmed. Identical existing note text cannot prove this request succeeded. `updateContactNote` replaces text and associations; `deleteContactNote` removes a note. Both are safe to repeat. Note IDs and contact IDs use Nimble's 24-character hexadecimal format.

Sign in to [Nimble CRM](https://app.nimble.com/) as an account administrator, open **Settings > API Token > Generate New Token**, name the token and choose Contacts scope, then copy it into Dex Web secret `api_key`. An administrator may need to grant API access under **Settings > Users**. The connector sends the token only in an Authorization Bearer header. See the [Nimble API reference](https://www.nimble.com/developers/docs/) and [token setup guide](https://support.nimble.com/en/articles/822159-generate-an-api-key-to-access-the-nimble-api).

Both queries retry transport failures, HTTP 429, timeout, and server failures. Definite rejections, malformed or oversized JSON, invalid input, and a missing contact select optional branches. The [Go](go/examples/contact-id-discovery/README.md), [Python](python/examples/contact_id_discovery/README.md), and [TypeScript](typescript/examples/contact-id-discovery/README.md) contact ID discovery Flows are runnable consumers. Provider requests and exact outcomes are recorded in [Go conformance scenarios](../../conformance/connectors/nimble/scenarios.json). Live Nimble authorization and responses remain unverified.

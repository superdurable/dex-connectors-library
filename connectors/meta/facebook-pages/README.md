# Facebook Pages connector

The Go, Python, and TypeScript connectors implement `listPosts` for a Page feed and `getPost` for one post ID. Go, Python, and TypeScript also implement `publishTextPost` for a plain-text Page post. The [Go Page post Flow](go/examples/page-posts/README.md), [Go post inspection Flow](go/examples/post-inspection/README.md), [Go publishing Flow](go/examples/publish-post/README.md), [Python publishing Flow](python/examples/post_publish/README.md), [Python post feed Flow](python/examples/page_posts/README.md), [TypeScript post feed Flow](typescript/examples/page-posts/README.md), and [TypeScript publishing Flow](typescript/examples/publish-post/README.md) are runnable consumers. Go-recorded provider scenarios cover both queries in all three languages and publishing in all three languages. The queries return only post ID, message, creation time, and permalink; they do not request comments, reactions, or audience data. Page event delivery remains to be implemented.

Create or select an app with Pages API access in [Meta for Developers](https://developers.facebook.com/apps/). Grant the token holder the Page tasks needed to read its feed. In [Graph API Explorer](https://developers.facebook.com/tools/explorer/), select the app, request `pages_show_list` and `pages_read_engagement` for reads and `pages_manage_posts` for publishing, then choose Get Token > Get Page Access Token. Save the complete token only in the Dex secret `page_access_token` field. Meta may require App Review and advanced access for production Pages. Find the numeric Page ID in Meta Business Suite > Settings > Business assets > Pages. `listPosts` returns post IDs that can be passed to `getPost`. Leave the versioned Graph API URL, timeout, and response limit at their displayed defaults unless your account needs a supported override.

The Queries retry transport failures, HTTP 429, request timeout, and server failures. HTTP 404 selects `notFound`; other definitive rejections select `providerRejected`; malformed or oversized JSON selects `invalidResponse`. Publishing sends one form-encoded POST to the Page feed. A durable fence permits safe retry after HTTP 429, 503, a Graph throttling code, or a failure before connection. Meta has no post idempotency key or read-back by Call ID, so an unknown outcome (a 5xx other than 503, 408, 409, any 4xx other than 400, 401, 403, 404, 411, 413, 414, 415, or 422, an interrupted or malformed response, or a connection lost after dispatch) resends while possible sends stay below the operation's `maxSends` (default 3), so the Page may show a duplicate post, and selects `uncertain` at the cap. A definite refusal selects `providerRejected` and is never resent; after an earlier possible send it selects `uncertain`. A post ID checkpointed by an earlier attempt completes the Step without resending. An unreadable checkpoint retries without sending. Inspect the Page feed before any manual retry after `uncertain`. Optional branches are unwired by default and fail the Flow. The token and provider error body are excluded from failures and Flow results.

Meta's [Page feed SDK edge](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/page.py) describes the underlying Graph API read and publish endpoints. Live Page authorization, Dex Web setup, and provider responses remain unverified.

# Facebook Pages connector

The Go, Python, and TypeScript connectors implement `listPosts` for a Page feed, `getPost` for one post ID, and `publishTextPost` for a plain-text Page post. Go also implements `updatePost` and `deletePost`. The [Go Page post Flow](go/examples/page-posts/README.md), [Go post inspection Flow](go/examples/post-inspection/README.md), [Go publishing and update Flows](go/examples/publish-post/README.md), [Python publishing Flow](python/examples/post_publish/README.md), [Python post feed Flow](python/examples/page_posts/README.md), [TypeScript post feed Flow](typescript/examples/page-posts/README.md), and [TypeScript publishing Flow](typescript/examples/publish-post/README.md) are runnable consumers. Go-recorded provider scenarios cover the declared operations in all three languages. The queries return only post ID, message, creation time, and permalink; they do not request comments, reactions, or audience data. Page event delivery remains to be implemented.

Create or select an app with Pages API access in [Meta for Developers](https://developers.facebook.com/apps/). Grant the token holder the Page tasks needed to read its feed. In [Graph API Explorer](https://developers.facebook.com/tools/explorer/), select the app, request `pages_show_list` and `pages_read_engagement` for reads and `pages_manage_posts` for publishing, then choose Get Token > Get Page Access Token. Save the complete token only in the Dex secret `page_access_token` field. Meta may require App Review and advanced access for production Pages. Find the numeric Page ID in Meta Business Suite > Settings > Business assets > Pages. `listPosts` returns post IDs that can be passed to `getPost`. Leave the versioned Graph API URL, timeout, and response limit at their displayed defaults unless your account needs a supported override.

The Queries retry transport failures, HTTP 429, request timeout, and server failures. HTTP 404 selects `notFound`; other definitive rejections select `providerRejected`; malformed or oversized JSON selects `invalidResponse`. Publishing sends one form-encoded POST to the Page feed. A durable fence permits safe retry after HTTP 429 or 503 or a failure before connection; an ambiguous response selects `uncertain` so Dex does not duplicate the post. Inspect the Page feed before any manual retry. `updatePost` replaces the complete message and `deletePost` removes the post; both repeat safely on an unknown outcome. Meta limits API deletion to select developers, so other apps may receive `providerRejected`. Optional branches are unwired by default and fail the Flow. The token and provider error body are excluded from failures and Flow results.

Meta's [Page Post API](https://developers.facebook.com/docs/graph-api/reference/page-post/) documents update and delete endpoints. Pass a post ID from `listPosts` to either Go write operation; `updatePost.message` is nonempty complete replacement text. Live Page authorization, Dex Web setup, and provider responses remain unverified.

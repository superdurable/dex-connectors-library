# Google Cloud Storage connector

The Go, [Python](python/README.md), and [TypeScript](typescript/README.md) connectors list one page of object identities, download a bounded object body, and upload an object through the [Cloud Storage JSON API](https://docs.cloud.google.com/storage/docs/json_api/v1). The runnable Go [object-list Flow](go/examples/objects/README.md), [download Flow](go/examples/download/README.md), and [upload Flow](go/examples/upload/README.md) use the static `google-cloud-storage` Dex Web connection. Object-created delivery remains to be implemented.

## Connection setup

In [Google Cloud Console](https://console.cloud.google.com/apis/credentials), select a project and enable Cloud Storage JSON API in **APIs & Services → Library**. Configure Google Auth Platform consent, audience, and test users as needed. Add the displayed `devstorage.read_write` scope, create a Web application under **Clients**, register the exact redirect URI shown in Dex Web, and save its Client ID and Client Secret there. Authorize a Google account with bucket access and offline access. Tokens remain Dex secrets.

Find the bucket name under **Cloud Storage → Buckets**. `listObjects` accepts the bucket name, optional object name prefix, page size from 1 through 1000 (default 100), and a page token from a previous response; only the bucket name is required, and a blank or omitted token reads the first page. It returns object names, immutable generation strings, and a next page token. Pass a returned name and optional generation to `downloadObject`; it returns content as Base64 plus the HTTP content type. Download size is limited by `maxResponseBytes` (default 2 MiB). The API origin and request timeout have manifest defaults. Object content is placed in a Flow result, so applications should only download content they intend to persist in Dex.

[Objects: list](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/list) and [download objects](https://docs.cloud.google.com/storage/docs/downloading-objects) define the two requests. Live Google OAuth authorization, Cloud Storage reads, and Dex Web field rendering have not been verified in this checkout.

`uploadObject` accepts a bucket, destination object name, complete Base64 content, and media type. It sends a [media upload](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/insert) with `ifGenerationMatch=0`, so it never overwrites a live object. On a precondition failure it reads the existing object's immutable generation and compares its bytes. The happy path means that the requested bytes are present, including when an earlier retry may have created them; `objectExists` means a different object is present at that name. The upload limit defaults to 2 MiB, can be raised to 64 MiB, and cannot exceed the response limit needed for confirmation. Object content travels through the Flow input and should be supplied only when the application intends Dex to persist it. Live Google upload behavior has not been verified.

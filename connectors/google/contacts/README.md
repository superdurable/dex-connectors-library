# Google Contacts connector

The Go, Python, and TypeScript connectors list, get, and create contacts through the [Google People API](https://developers.google.com/people/api/rest). Their runnable [Go](go/examples/contacts/README.md), [Python](python/examples/contacts/README.md), and [TypeScript](typescript/examples/contacts/README.md) list Flows and corresponding creation Flows use the static `google-contacts` Dex Web connection.

## Connection setup

In [Google Cloud Console](https://console.cloud.google.com/apis/credentials), select a project and enable **People API** under **APIs & Services → Library**. Configure OAuth consent and add the `contacts` scope under **Data Access**. Add test users while an External app remains in Testing. Create a Web application under **Clients**, register the exact redirect URI displayed by Dex Web, and save its Client ID and Client Secret in the connection. Authorize a Google account with offline access. Tokens remain Dex secrets.

`listContacts` uses a fixed `names,emailAddresses` field mask and returns one page of projected contacts with an optional next page token. Pass a returned `people/{id}` resource name to `getContact`. The optional page size defaults to 100 and can be set from 1 through 1000; an omitted or blank page token reads the first page. Both operations return only the first display name and email address; either can be blank. The API origin, timeout, and response limit have manifest defaults; override them only for a trusted gateway or a known operational need.

The [connections.list](https://developers.google.com/people/api/rest/v1/people.connections/list) and [people.get](https://developers.google.com/people/api/rest/v1/people/get) methods define these read operations. Live Google authorization and API behavior have not been verified in this checkout.

`createContact` requires a given name and accepts optional family name and email address, which callers may omit. It sends one People API create request. Google does not offer a create-contact idempotency key, so a durable single-dispatch fence counts possible sends. A 429, a 503, or a request that never left the process retries. An unknown outcome, such as a timeout, a lost connection, a 5xx, a 409, or an unreadable response, is resent until the send cap (`maxSends`, default 3) is reached; when an earlier attempt saved the contact's resource name, the next attempt reads that contact back instead of creating another. A definite refusal (400, 401, 403, 404, 411, 413, 414, 415, or 422) selects `providerRejected` on the first send and is never resent; after an earlier unconfirmed send it selects `uncertain`. An `uncertain` result appears only at the send cap and means the user should inspect Contacts before creating another. The [people.createContact](https://developers.google.com/people/api/rest/v1/people/createContact) method defines the write request.

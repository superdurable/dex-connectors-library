# LinkedIn Python connector

The `getAuthenticatedProfile` Query reads bounded OpenID Connect UserInfo claims and requires a verified email. The `profileChanged` poll Trigger delivers one event whenever the connected member's own profile claims change (name, given and family name, email, email verification, picture, or locale); it never watches other members. Install `dex-connector-linkedin==0.2.0`, which requires `dex-connectors-sdk>=0.12.0`. Project connections use generated OAuth refresh and credential wiring.

`new_project_profile_trigger_runner` loads saved bindings and records each change in the binding's project Trigger inbox before the profile commits in its poll cursor; `new_profile_trigger_runner` takes targets and cursor stores directly, and `new_profile_changed_trigger` keeps the cursor in memory, so it records a new baseline on every start. The first poll records a baseline and delivers nothing. The connection's `pollInterval` defaults to 15 minutes and must be at least one minute. Cursor documents and event IDs match the Go connector byte for byte, so Go and Python replicas share a binding. See the [connector README](../README.md#profilechanged-trigger) for the tracked claims, picture re-signing, resets, and rate limits.

The runnable examples are `examples/authenticated_profile` and [`examples/profile_changed`](examples/profile_changed/README.md).

Run `uv sync --locked` and `uv run pytest -q tests` from this directory. `tests/fixtures/profile-changed-go-fetcher-cases.json`, recorded from the Go fetcher, is replayed through the Python fetcher, comparing every request, cursor token, event ID, payload, and poll signal. With `dexcli dev` running, set `DEX_FLOW_SERVICE_ADDRESS` and run `uv run pytest -q examples/authenticated_profile/integration_test.py examples/profile_changed/integration_test.py`. The examples use the generated OAuth project connection and a static connection name. Live LinkedIn authorization, UserInfo behavior, and live profile polling have not been verified.

# Douyin mini app connector

This connector uses the official [mini app behavior analysis API](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/server/operation/data-analysis/user-analysis/behavior-analysis-datav3) to read aggregate user and opening counts for one completed day. It uses the [non-service-provider client_token exchange](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/server/basic-abilities/interface-request-credential/non-user-authorization/get-client_token) at `POST https://open.douyin.com/oauth/client_token/`, caches the token in worker memory until expiry, and sends it only in the `access-token` header. Individual behavior records and raw provider messages are discarded. Douyin Open Platform is operated by [Beijing Weiboshijie Technology Co., Ltd. and affiliates](https://open.douyin.com/platform/resource/docs/operation-standard/agreement-protocol/).

In the [Douyin mini app console](https://developer.open-douyin.com/), open 开发 > 开发配置 for AppID/client_key and AppSecret/client_secret. Save them in Dex Web Connections. The [official token guide](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/tutorial/beginner/token/) gives that page path. This connector supports applications calling their own analytics. Service-provider delegation requires a separate merchant authorization path and is not implemented.

The query accepts a date within the previous 90 days and available by 10:00 China Standard Time on the following day. It requests midnight through 23:59:59 in China Standard Time and returns only `data.sum` counts. The provider documentation does not explicitly state its analytics timezone; verify that this interval matches your reporting day in a live account. Run the [Go example Flow](go/examples/get-behavior-summary/) or [Python example Flow](python/examples/get_behavior_summary/) with a user-controlled connection. The Python package replays Go-recorded provider scenarios and verifies token reuse and retry through a real Dex Worker and Client.

# Telegram Bot connector

The first Go release reads chat metadata with `getChat` and sends plain text with `sendMessage`. Supply a numeric chat ID or public `@username` accessible to the bot. `getChat` returns the stable numeric ID, chat type, title, and public username. `sendMessage` returns the created message ID, numeric destination ID, and Unix creation time; it never persists the message text in its result.

Create a bot with [BotFather](https://t.me/BotFather) using `/newbot`, or open `/mybots` and choose an existing bot. Store its full `numeric-ID:secret` token in the Dex `bot_token` credential. Add the bot to the target chat. The Bot API requires that token in the request path; the connector does not log that path or include it in Dex results, failures, receipts, or Flow input. Revoke an exposed token in BotFather.

`getChat` selects `found`, `notFound`, `providerRejected`, `invalidResponse`, or `defect`. HTTP 429, 503, other server errors, and transport failures retry under the default one-hour policy. `sendMessage` selects `sent`, `providerRejected`, `uncertain`, or `defect`. A sync Execute checkpoint prevents a duplicate send on later attempts. Telegram has no send idempotency key: a 500, interrupted response, or unconfirmed dispatch selects `uncertain` rather than sending again. A definite 429 or 503 retries after checkpointing that no message was created. See the runnable [chat lookup](go/examples/chat-lookup/README.md) and [message send](go/examples/send-message/README.md) examples. Receiving messages from the backlog remains a future addition whose delivery and duplicate semantics require separate verification.

# Telegram Bot connector

The Go, Python, and TypeScript connectors read chat metadata with `getChat` and send plain text with `sendMessage`. Supply a numeric chat ID or public `@username` accessible to the bot. `getChat` returns the stable numeric ID, chat type, title, and public username. `sendMessage` returns the created message ID, numeric destination ID, and Unix creation time; it never persists the message text in its result.

Create a bot with [BotFather](https://t.me/BotFather) using `/newbot`, or open `/mybots` and choose an existing bot. Store its full `numeric-ID:secret` token in the Dex `bot_token` credential. Add the bot to the target chat. The Bot API requires that token in the request path; the connector does not log that path or include it in Dex results, failures, receipts, or Flow input. Revoke an exposed token in BotFather.

`getChat` selects `found`, `notFound`, `providerRejected`, `invalidResponse`, or `defect`. HTTP 429, 503, other server errors, and transport failures retry under the default one-hour policy. `sendMessage` selects `sent`, `providerRejected`, `uncertain`, or `defect`. A sync Execute checkpoint counts possible sends across attempts. Telegram has no send idempotency key or message read-back: an unknown outcome (a 5xx other than 503, 408, 409, any 4xx other than 400, 401, 403, 404, 411, 413, 414, 415, or 422, an interrupted or malformed response, or a connection lost after dispatch) retries and resends while possible sends stay below the operation's `maxSends` (default 3), so the chat may show a duplicate, and selects `uncertain` at the cap. A definite refusal selects `providerRejected` and is never resent; after an earlier possible send it selects `uncertain`. A response that reports acceptance without a complete message, or a saved message ID from an earlier attempt, selects `uncertain` without resending. An unreadable checkpoint retries without sending. A definite 429 or 503 retries after checkpointing that no message was created. Both operations wait for the `Retry-After` header or, when it is absent, the error body's `parameters.retry_after` seconds. The [Go-recorded scenarios](../../conformance/connectors/telegram/scenarios.json) verify the Python and TypeScript provider decisions. See runnable examples in [Go](go/examples/send-message/README.md), [Python](python/README.md), and [TypeScript](typescript/README.md). Receiving messages from the backlog remains a future addition whose delivery and duplicate semantics require separate verification.

# Telegram Bot connector

The Go connector provides `editMessageText`, `deleteMessage`, `pinChatMessage`, `unpinChatMessage`, `sendChatAction`, `answerCallbackQuery`, `answerInlineQuery`, `getFile`, `getChat`, `getChatAdministrators`, `getChatMember`, `leaveChat`, `setChatDescription`, `setChatTitle`, `sendMessage`, `sendAnimation`, `sendAudio`, `sendDocument`, `sendPhoto`, `sendSticker`, `sendVideo`, `sendLocation`, and `sendMediaGroup`. Python and TypeScript continue to provide `getChat` and `sendMessage`. Supply a numeric chat ID or public `@username` accessible to the bot. Chat member and administrator results contain numeric user IDs and statuses, without names or usernames. Sent-message results contain provider identities and Unix creation times, without captions, file references, or text.

Create a bot with [BotFather](https://t.me/BotFather) using `/newbot`, or open `/mybots` and choose an existing bot. Store its full `numeric-ID:secret` token in the Dex `bot_token` credential. Add the bot to the target chat. The Bot API requires that token in the request path; the connector does not log that path or include it in Dex results, failures, receipts, or Flow input. Revoke an exposed token in BotFather.

`getChat` selects `found`, `notFound`, `providerRejected`, `invalidResponse`, or `defect`. HTTP 429, 503, other server errors, and transport failures retry under the default one-hour policy. `sendMessage` selects `sent`, `providerRejected`, `uncertain`, or `defect`. A sync Execute checkpoint prevents a duplicate send on later attempts. Telegram has no send idempotency key: a 500, interrupted response, or unconfirmed dispatch selects `uncertain` rather than sending again. A definite 429 or 503 retries after checkpointing that no message was created. Both operations wait for the `Retry-After` header or, when it is absent, the error body's `parameters.retry_after` seconds. The [Go-recorded scenarios](../../conformance/connectors/telegram/scenarios.json) verify the Python and TypeScript provider decisions. See runnable examples in [Go](go/examples/send-message/README.md), [Python](python/README.md), and [TypeScript](typescript/README.md). Receiving messages from the backlog remains a future addition whose delivery and duplicate semantics require separate verification.

The new chat operations follow the [Telegram Bot API](https://core.telegram.org/bots/api). `leaveChat`, `setChatDescription`, and `setChatTitle` are safe to repeat because they leave or set an absolute value. The bot needs administrator rights for title and description changes. An empty description clears it; titles contain 1 to 128 characters and descriptions at most 255. Query results exclude profile details. The [chat example](go/examples/chat-lookup/README.md) exercises title replacement against a mock-backed real Dex Worker.

`answerCallbackQuery` acknowledges a callback ID and optionally displays up to 200 characters; blank text shows no notification. `answerInlineQuery` accepts a JSON array of at most 50 Bot API inline result objects. These acknowledgements and result replacements are safe to repeat. `getFile` returns the file ID, unique ID, optional byte size, and provider path. The Bot API requires the bot token to download a file, so the connector never builds a token-bearing URL in Flow Results. The [file example](go/examples/chat-lookup/README.md) runs against a mock-backed real Dex Worker; binary download is not implemented.

`editMessageText` replaces plain text and treats Telegram's definitive “message is not modified” response as already applied. `deleteMessage`, `pinChatMessage`, and `unpinChatMessage` repeat safely for a selected message ID and recognize definitive already-done responses. Deletion follows Telegram's [48-hour and permission limits](https://core.telegram.org/bots/api#deletemessage). `sendChatAction` shows a transient activity for at most five seconds and can be repeated harmlessly. The [message example](go/examples/send-message/README.md) exercises text replacement with a mock-backed real Dex Worker.

Media sends accept an existing Telegram file ID or public HTTPS URL; they do not upload local files. `sendMediaGroup` accepts two through ten photos or videos. `sendLocation` accepts latitude and longitude in degrees. These sends use a three-send limit when a 5xx or response loss leaves the outcome unknown; after the cap, they select `uncertain`. Telegram has no idempotency key for these methods, so a duplicate is possible after an unknown response. The [message example](go/examples/send-message/README.md) exercises `sendPhoto` through a mock-backed real Dex Worker. See the [Bot API](https://core.telegram.org/bots/api) for media size and format limits.

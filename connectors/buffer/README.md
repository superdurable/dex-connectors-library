# Buffer connector

The Go, Python, and TypeScript `getChannel` Query reads a connected channel's ID, name, and social service using Buffer's [GraphQL channel query](https://developers.buffer.com/reference). A null channel or only `NOT_FOUND` GraphQL errors select optional `notFound`. GraphQL errors with [`extensions.code`](https://developers.buffer.com/guides/error-handling.html) `RATE_LIMIT_EXCEEDED` or `UNEXPECTED` retry; any other code selects `providerRejected`. HTTP 429, server failures, and transport failures retry.

Go also provides `listOrganizations`, `listChannels`, `getPost`, and `listPosts` as safe Queries, plus `createPost` (limited), `editPost` (safe), and `deletePost` (safe) Mutations. `listPosts` accepts an organization ID, a page size from 1 to 100 (zero uses 20), and an opaque `after` cursor. `createPost` adds a post to one channel's queue; an unknown send may be retried up to the Step's `MaxSends` cap and then selects `uncertain`. `editPost` replaces text and, when provided, assets on one post. `deletePost` removes the Buffer post; a previously published network post may remain online. The Go-only operations follow the [Buffer GraphQL API](https://developers.buffer.com/reference.html); Python and TypeScript retain `getChannel` only.

Go post creation, scheduling, publishing, and editing accept `assets` with image, video, or document URLs. Buffer hosts no upload endpoint: host files at direct public HTTPS URLs and keep them available until publication. Signed URLs, URL queries, embedded credentials, and fragments are rejected from Flow input. Documents require a thumbnail URL and title; videos can include `thumbnailOffsetMs`. Text or at least one asset is required. See Buffer's [media hosting guide](https://developers.buffer.com/guides/hosting-media.html).

The Go `createIdea` Mutation creates one text idea in an organization. It requires the organization ID from `listOrganizations`, a nonempty title, and nonempty text. Unknown outcomes are retried under a three-send cap and select `uncertain` when exhausted because Buffer does not expose a read-back key for a newly created idea. See Buffer's [Create Idea example](https://developers.buffer.com/examples/create-idea.html).

Go also provides `createScheduledPost` and `publishPostNow`, both limited Mutations with a three-send cap. They use Buffer's `createPost` GraphQL mutation with `customScheduled` and `shareNow` modes respectively. `createScheduledPost` requires `dueAt` as an RFC 3339 timestamp and sends it in UTC; `publishPostNow` accepts a channel ID and nonempty text. An unknown result can select `uncertain`, including after Buffer may have published the post. See Buffer's [scheduled post example](https://developers.buffer.com/examples/create-scheduled-post.html) and [REST migration guide](https://developers.buffer.com/guides/rest-migration.html).

## Connect

In [Buffer Settings → API](https://publish.buffer.com/settings/api), create an account API key and copy its full secret into `apiKey` in Dex Web Connections. The key can access all organizations and channels in the account. Leave `baseUrl`, `timeout`, and `maxResponseBytes` blank for their displayed defaults. `listOrganizations` supplies opaque organization IDs for `listChannels` and `listPosts`. `listChannels` supplies channel IDs for `getChannel` and `createPost`. `listPosts` and `createPost` supply post IDs for `getPost`, `editPost`, and `deletePost`. All IDs are required and must be copied exactly; blank is invalid.

Runnable examples are in [`go/examples/channel-read`](go/examples/channel-read), [`python/examples/channel_read`](python/examples/channel_read), and [`typescript/examples/channel-read`](typescript/examples/channel-read). Go records provider scenarios; Python and TypeScript replay them. Real Buffer authorization and live provider behavior remain unverified without a user-controlled API key.

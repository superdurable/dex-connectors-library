# Constant Contact connector

The Go connector creates, updates, reads, and searches contacts and manages contact lists through the [Constant Contact V3 API](https://developer.constantcontact.com/api_guide/contacts/contacts-get-one). `createContact` accepts a unique email address, optional names, `createSource` (`Account` or `Contact`), and the actual `emailPermission` (`explicit`, `implicit`, or `not_set`). Supply only permission the contact has granted; see [Constant Contact's creation guidance](https://developer.constantcontact.com/api_guide/contacts/contacts-post-one). `updateContact` changes selected name, job title, and company fields: a nil field preserves its current value; an empty string clears it. It first reads all core fields and supplies them to Constant Contact's [full-resource PUT](https://developer.constantcontact.com/api_guide/contacts/contacts-put), preserving email permission and omitted subresources. Concurrent changes between that read and PUT can still be overwritten. `getContact` and `listContacts` return selected identity and email fields; `deleteContact` removes one contact and its list memberships. `getContactList`, `listContactLists`, `createContactList`, `updateContactList`, and `deleteContactList` cover list management. List deletion starts an asynchronous provider activity and returns its `activityId`; inspect that activity to confirm completion.

Create a V3 application in [My Applications](https://app.constantcontact.com/pages/dma/portal/), choose Authorization Code Flow with rotating refresh tokens, register the exact Dex Web redirect URI, and generate the Client Secret. The connection requests `contact_data` for contacts and lists and `offline_access` for refresh. The authorized account also needs the relevant contacts read/write or contact-list read/write privileges. New applications can initially be authorized only by their creator until Constant Contact approves wider access. [Constant Contact's setup guide](https://developer.constantcontact.com/api_guide/getting-started/getting-started) describes the application settings.

Run the [contact inspection example](go/examples/contact-inspection/README.md) with the static `constantcontact` connection. Its read input uses a V3 contact UUID; its list input accepts a `limit` from 1 to 1000 and optional exact `name`. The create Flow uses the documented email, permission, and source fields. Contact and list creation use a bounded three-send fence, checking the unique email or list name before any resend; when read-back cannot confirm an earlier write after the cap, the operation selects `uncertain`. A definitive 404 selects `notFound`; other provider rejections and malformed or oversized responses select optional branches. Unwired optional branches fail the Flow.

Python and TypeScript continue to implement only `getContact` and replay its Go-recorded scenarios. OAuth authorization and real Constant Contact requests have not been verified against a live account.

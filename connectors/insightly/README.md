# Insightly CRM connector

The Go and Python connectors read a bounded page of contact IDs, names, and email addresses with `listContacts`, then read one contact by ID with `getContact`. Custom fields, links, and other provider data remain outside Flow results. The page request sets `top` from 1 to 500 and a nonnegative `skip`; the contact lookup requires a positive decimal ID.

Sign in to [Insightly CRM](https://login.insightly.com/), open the top-right user icon, then **User Settings > User Settings > API**. Copy the personal API key into the Dex Web secret `api_key` field. Copy the pod-specific API URL shown beside it into `baseUrl` if the displayed na1 default is not your pod. The connector sends the key as the HTTP Basic username with an empty password. See the [Insightly API overview](https://api.na1.insightly.com/v3.1/Help/_OverviewResource) and [credential guidance](https://support.insight.ly/en-us/Knowledge/article/9549/Find_your_API_key_and_url/).

Both queries retry transport failures, HTTP 429, timeout, and server failures. Definite rejections, malformed or oversized JSON, invalid input, and a missing contact select optional branches. The [Go contact discovery Flow](go/examples/contact-discovery/README.md) and [Python contact discovery Flow](python/examples/contact_discovery/README.md) are runnable consumers. Their provider requests and exact outcomes are checked against [Go conformance scenarios](../../conformance/connectors/insightly/scenarios.json). Live Insightly authorization and responses remain unverified.

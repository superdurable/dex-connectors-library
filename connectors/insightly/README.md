# Insightly CRM connector

The Go, Python, and TypeScript connectors read a bounded page of contact IDs, names, and email addresses with `listContacts`, then read one contact by ID with `getContact`. These two identity queries keep custom fields and links outside Flow results. The page request sets `top` from 1 to 500 and an optional nonnegative `skip`, where an omitted or zero `skip` starts at the first contact; the contact lookup requires a positive decimal ID.

Go also supports `listRecords`, `getRecord`, `searchRecords`, `createRecord`, `updateRecord`, and `deleteRecord` for contacts, leads, organisations, opportunities, projects, and tasks. These operations preserve the provider's uppercase field names and JSON values, including custom fields. Supply a page size from 1 to 500 for lists and searches. Search uses Insightly's exact `field_name` and `field_value` query parameters. The record ID field is determined by the selected resource, and update writes it automatically in the v3.1 partial `PUT` body. `deleteRecord` treats HTTP 404 as already deleted.

Creation has a limited repeat tier with at most three possible sends because Insightly does not document a create idempotency key. A returned record ID is read back before any later send; when no ID is known, an unknown outcome can be resent within the cap and selects `uncertain` at the cap. Field requirements depend on the resource and account configuration. Check an existing record's JSON and the [v3.1 API reference](https://api.na1.insightly.com/v3.1/Help) before creating a record. The new operations are Go only; Python and TypeScript retain their existing contact identity queries.

Sign in to [Insightly CRM](https://login.insightly.com/), open the top-right user icon, then **User Settings > User Settings > API**. Copy the personal API key into the Dex Web secret `api_key` field. Copy the pod-specific API URL shown beside it into `baseUrl` if the displayed na1 default is not your pod. The connector sends the key as the HTTP Basic username with an empty password. See the [Insightly API overview](https://api.na1.insightly.com/v3.1/Help/_OverviewResource) and [credential guidance](https://support.insight.ly/en-us/Knowledge/article/9549/Find_your_API_key_and_url/).

Both queries retry transport failures, HTTP 429, timeout, and server failures. Definite rejections, malformed or oversized JSON, invalid input, and a missing contact select optional branches. The [Go contact discovery Flow](go/examples/contact-discovery/README.md), [Python contact discovery Flow](python/examples/contact_discovery/README.md), and [TypeScript contact discovery Flow](typescript/examples/contact-discovery/README.md) are runnable consumers. Their provider requests and exact outcomes are checked against [Go conformance scenarios](../../conformance/connectors/insightly/scenarios.json). Live Insightly authorization and responses remain unverified.

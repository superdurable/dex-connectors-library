# GitHub Connector for TypeScript

`@superdurable/connector-github` provides Dex Query operations for an authenticated profile, public repositories, merged pull requests, pull request files, releases, commits, and repository issues (`newListIssuesStep`), and four issue Mutations: `createIssue` (`newCreateIssueStep`), `setIssueState` (`newSetIssueStateStep`), which closes or reopens one issue, `replaceIssueLabels` (`newReplaceIssueLabelsStep`), which replaces an issue's labels, and `createIssueComment` (`newCreateIssueCommentStep`), which comments on an issue. The generated Step factories and connection bindings use the same connector and branch IDs as the Go module, and its conformance test replays every Go-recorded scenario.

A connection uses `github-oauth` (the default, `read:user user:email`) or `github-oauth-repository` (`repo`), exported as `PublicAuthMethodID` and `RepositoryAuthMethodID`. Every operation requires the exact scopes of the connection's method. The issue Mutations need `github-oauth-repository` and select `insufficientScope` on any other method without calling GitHub; the profile, repository, change, and release queries select `insufficientScope` on a repository connection. See the [connector README](../README.md#repository-issues) for the duplicate protection: a hidden marker holding a digest of the Call ID, the single-dispatch fence with `repeatOnUnknown: limited` and at most 3 sends, the saved issue number, and read-back before any resend. A Step may set `maxSends` from 1 to 10. `setIssueState` sends one `PATCH` with an absolute state and an optional reason (`completed` or `not_planned` with `closed`, `reopened` with `open`; exported as `IssueStateClosed`, `IssueStateReasonNotPlanned`, and the like), declares `repeatOnUnknown: safe`, and retries an unknown outcome by sending the same update again. `replaceIssueLabels` sends one `PUT` with the full label set and is `safe` the same way. `createIssueComment` follows `createIssue`: the same hidden Call ID marker, the single-dispatch fence with `repeatOnUnknown: limited` and at most 3 sends, the saved comment ID, and read-back over the issue's first and newest comment pages before any resend.

The [issue filing example](examples/issue-filing/README.md) files an issue unless an open one with the same title is already tracked, and, when the input asks, comments on the created issue, replaces its labels, and closes it.

The OAuth connection requests `read:user`, `user:email`, and `offline_access`. Dex stores the access and rotating refresh tokens in the named project connection. The package uses manifest-generated credential decoders and refresh declarations. Decoded `Credentials` carry an optional `authMethodId`; a credential stored without a method decodes as `github-oauth`. GitHub Enterprise Server may return a non-expiring access token without refresh material.

Use `newProjectConnection(project, ConnectionName)` in a Worker after loading its Dex project. The [repository releases example](examples/repository-releases/README.md) is a runnable Flow with a static connection name and a persisted release page. Its optional failure branches are intentionally unwired, so an authorization or provider rejection fails the Flow.

The package requires Node.js 22 or 24 and a Dex TypeScript SDK meeting the declared peer minimum. `npm run check` runs the package tests, type checker, and linter. `npm run test:integration` runs the example through a real Dex Worker and Client against the server named by `DEX_FLOW_SERVICE_ADDRESS`.

Connection settings include `baseUrl`, `apiVersion`, `timeout` (positive Go duration, converted to milliseconds), `maxResponseBytes`, and bounds for repository counts and returned text. The connector never places credentials or raw provider error bodies in Flow state. See the [connector contract](../README.md) for operation details and authorization guidance.

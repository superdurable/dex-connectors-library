# GetResponse connector

The Go connector lists contacts with `listContacts`, reads one with `getContact`, queues one with `createContact`, updates supplied fields with `updateContact`, and removes one with `deleteContact`. Python and TypeScript continue to provide the two reads. Contact results expose only ID, email, and name; custom fields and embedded details stay out of Flow results. These operations cover GetResponse SMB accounts. GetResponse MAX needs an additional `X-Domain` header and remains outside this release.

Open [GetResponse Integrations and API](https://app.getresponse.com/api), generate or copy your API Key, and save it in the Dex Web connection's secret `api_key` field. The connector sends it in the `X-Auth-Token` header with the required `api-key` prefix. Leave `baseUrl` blank for the displayed SMB API default. See [authentication](https://apidocs.getresponse.com/v3/authentication), [contact listing](https://apidocs.getresponse.com/v3/case-study/segments-manual), and [limits](https://apidocs.getresponse.com/v3/limits).

Both reads retry transport failures, HTTP 429, request timeout, and server failures. `getContact` selects `notFound` on a definitive 404. `createContact` uses a three-send limit and checks the list for the same email before any resend after an unknown outcome; it selects `uncertain` when a queued contact cannot be confirmed at the limit. `updateContact` uses absolute field values and `deleteContact` repeats safely. Provider rejections and malformed or oversized responses select optional branches. The [contact-inspection Flow](go/examples/contact-inspection/README.md) now also demonstrates `updateContact` against the same static connection. The Python and TypeScript packages replay only their declared read scenarios. Live GetResponse authorization remains unverified.

For a contact create, find the list token at [GetResponse Contacts > Lists > Actions > Settings](https://app.getresponse.com/api), under General > LIST TOKEN; use that alphanumeric value as `campaignId`, an email address as `email`, and an optional display name as `name`. A blank name uses GetResponse's default. The API may queue contact creation, and double opt-in can delay visibility. For an update or delete, obtain the alphanumeric `contactId` from `listContacts` or `getContact`; `updateContact` requires at least one of `email` or `name`. See the provider's [contact creation guide](https://apidocs.getresponse.com/v3/case-study/adding-contacts) and [API reference](https://apireference.getresponse.com/).

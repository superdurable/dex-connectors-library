# Copper CRM connector

All three language packages read lead status IDs and names with `listLeadStatuses` and one lead's public metadata with `getLead`. Go also provides `createPerson`, `getPerson`, `listPeople`, `updatePerson`, and `deletePerson`. `listPeople` reads a page from Copper's [people search endpoint](https://developer.copper.com/people/list-people-search.html), with optional full-name and work-email filters. `pageNumber` starts at one; zero selects the first page. `pageSize` accepts 1–200; zero uses Copper's default of 20. Person results contain the numeric ID, name, first work email, and notes; custom fields and other private data stay out of Flow state. A positive decimal ID is required for person lookup, update, and deletion.

Go also provides `createCompany`, `getCompany`, `listCompanies`, `updateCompany`, and `deleteCompany` through the [Companies API](https://developer.copper.com/companies/overview.html). Company creation requires an email domain, which Copper keeps unique, so a later attempt can search by domain and exact name before resending. `listCompanies` supports page number, size, name, and email-domain filters. Updates send only name and details; deletion is permanent. Company custom fields remain outside persisted results.

For a private integration, sign in as an admin to [Copper](https://app.copper.com/), open **Settings > Integrations > API Keys**, and select **Generate API Key**. Save the full key in the Dex Web secret `api_key` field and the generating user's full email address in `user_email`. Copper requires both headers plus `X-PW-Application: developer_api`. Leave `baseUrl` blank for the Developer API v1 default. See the [Copper authentication guide](https://developer.copper.com/introduction/authentication.html), [request headers and rate limits](https://developer.copper.com/introduction/requests.html), [lead statuses](https://developer.copper.com/leads/list-lead-statuses.html), and [lead lookup](https://developer.copper.com/leads/fetch-a-lead-by-id.html).

Queries and repeatable update/delete writes retry transport failures, HTTP 429, and server failures. Person creation is a limited repeat: a durable dispatch fence caps possible sends at three, and a later attempt searches the work email before resending. A conclusive provider rejection selects an optional branch; an unconfirmed creation at the cap selects `uncertain`. The [Go person lookup Flow](go/examples/person-lookup/README.md), [Go lead status discovery Flow](go/examples/lead-status-discovery/README.md), [Python lead status discovery Flow](python/examples/lead_status_discovery/README.md), and [TypeScript lead status discovery Flow](typescript/examples/lead-status-discovery/README.md) are runnable consumers. Provider requests and exact outcomes are recorded in [Go conformance scenarios](../../conformance/connectors/copper/scenarios.json). Live Copper authorization and responses remain unverified. See [Copper People API](https://developer.copper.com/people/overview.html) for person fields and lifecycle.

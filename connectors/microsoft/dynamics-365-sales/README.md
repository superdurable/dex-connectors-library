# Microsoft Dynamics 365 Sales connector

`findContact` searches the [Dataverse Web API](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/webapi/retrieve-entity-using-web-api) for a contact with an exact primary email address. It requests at most two records. One match returns `contactId`, `fullName`, and `emailAddress`; zero matches select `missing`, and two matches select `multipleMatches`. Token and query throttling, HTTP 408/5xx, and transport failures retry. Rejection, malformed or oversized responses, and invalid input select optional branches.

This release uses an Entra confidential application and a [client credentials token request](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-client-creds-grant-flow). In [Entra admin center](https://entra.microsoft.com), create an app registration, copy its tenant and client UUIDs, then create a client secret and store only its Value in Dex Web's secret `client_secret` field. In [Power Platform admin center](https://admin.powerplatform.microsoft.com), open the target environment, copy its Environment URL, and create an application user for that app with a security role permitted to read Contact. The connector requests a fresh `environmentUrl/.default` token inside the Step and never stores it in Flow state. Leave timeout and maxResponseBytes blank for their displayed defaults. Rotate the client secret before expiration.

The [Go](go/examples/contact-lookup/README.md), [Python](python/examples/contact_lookup/README.md), and [TypeScript](typescript/examples/contact-lookup/README.md) examples run the same typed Flow. [Go-recorded conformance scenarios](../../../conformance/connectors/microsoft/dynamics-365-sales/scenarios.json) cover token acquisition, contact lookup, optional branches, and retry classification across all three languages. Mock-backed real Dex Worker tests are included. Live Microsoft authorization and contact lookup have not been verified.

# Campaign Monitor connector

Go campaign operations include `listCampaigns` and `getCampaignSummary` safe Queries; `createDraftCampaign`, `sendCampaign`, and `sendCampaignPreview` limited Mutations with three-send caps; and `unscheduleCampaign` and `deleteCampaign` safe Mutations. Drafts import HTML from an HTTPS URL and require sender, subject, and at least one list or segment ID. `sendCampaign` requires a confirmation email and sends immediately when `sendDate` is blank; a `YYYY-MM-DD HH:MM` value schedules the campaign in the client's timezone. It can reach the campaign's full audience and may select `uncertain` after an unknown outcome. `sendCampaignPreview` sends to one to five provided email addresses and may likewise select `uncertain`. `unscheduleCampaign` moves a scheduled campaign back to drafts. `listCampaigns` accepts `draft`, `scheduled`, or `sent`; sent results are paged. See the provider's [campaign API](https://www.campaignmonitor.com/api/v3-3/campaigns/) and [client campaign listings](https://www.campaignmonitor.com/api/v3-3/clients/).

Go segment operations include `listSegments` and `getSegment` safe Queries, `createSegment` limited with a three-send cap and list read-back by title, and `updateSegment` and `deleteSegment` safe Mutations. Rule groups are optional on creation; a nonnil `ruleGroups` value on update replaces the segment's complete rule set, while nil preserves it. Rule types and clauses follow the provider's [segment rules](https://www.campaignmonitor.com/api/v3-3/segments/). After creating or changing rules, allow for provider calculation before using a segment to send a campaign. A system segment or a segment attached to a draft campaign may reject deletion.

Go `getList` reads basic list settings; `createList` (limited) creates a list by client ID and unique title, checks that client's lists by title after an unknown send, and selects `uncertain` after the three-send cap if unconfirmed. `updateList` and `deleteList` are safe Mutations by list ID. Create and update require `UnsubscribeSetting` as `AllClientLists` or `OnlyThisList`; optional landing page URLs must be HTTPS. Update explicitly disables adding prior unsubscribes to the suppression list and scrubbing active subscribers. Deleting a list removes it from Campaign Monitor and may be rejected while a draft campaign uses it. See the provider's [list management API](https://www.campaignmonitor.com/api/v3-3/lists/).

Go `listSubscribers` reads a page of active, unconfirmed, unsubscribed, bounced, or deleted subscribers for a list ID. Blank state selects active; page number and size default to 1 and 100, and the size must be at most 1000. Its results include only email, name, state, and pagination counts. Continue by incrementing `pageNumber` through `numberOfPages`. See the provider's [list subscriber pages](https://www.campaignmonitor.com/api/v3-3/lists/).

The Go, Python, and TypeScript `listClients` Queries return client IDs and names visible to the connected account. It does not return the client API keys or billing details. Go also provides `listSubscriberLists` and `getSubscriber` safe Queries, plus `upsertSubscriber`, `updateSubscriber`, `deleteSubscriber`, and `unsubscribeSubscriber` safe Mutations. Python and TypeScript retain `listClients` only.

`listSubscriberLists` accepts a client ID from `listClients` and returns list IDs. The subscriber operations take a list ID and full email address. `upsertSubscriber` adds the email or updates its name when it exists; Campaign Monitor queues additions, so a successful response does not mean immediate visibility. `updateSubscriber` replaces the name of an existing email and selects `notFound` for a missing subscriber. `deleteSubscriber` marks an active email deleted without adding it to the suppression list. `unsubscribeSubscriber` stops campaign delivery to an active subscriber and applies the list's suppression setting; if the provider says the address is no longer in the list, it reads back the subscriber state before confirming success. Upsert and update disable resubscription and autoresponder restarts. Blank IDs, emails, and required names are invalid. See the provider's [subscriber API](https://www.campaignmonitor.com/api/v3-3/subscribers/) and [client lists API](https://www.campaignmonitor.com/api/v3-3/clients/).

To connect an account you control, sign in at [Campaign Monitor](https://login.createsend.com/l), open Profile image > Account settings > API keys ([guide](https://help.campaignmonitor.com/articles/Knowledge/api-keys)), show or generate the account API key, and save it in the Dex Web secret `api_key` field. The connector uses the key as the HTTP Basic username with an empty password. Leave `baseUrl` blank for the displayed API v3.3 default. Campaign Monitor recommends OAuth for public integrations. See [API authentication](https://www.campaignmonitor.com/api/v3-3/getting-started/) and [account API](https://www.campaignmonitor.com/api/v3-3/account/).

Queries and Mutations retry transport failures, HTTP 429, timeout, and server errors. Definite provider rejections and malformed or oversized responses select optional branches. The [Go client discovery Flow](go/examples/client-discovery/README.md) now lists one client's subscriber lists; [Python](python/examples/client_discovery/README.md) and [TypeScript](typescript/examples/client-discovery/README.md) examples retain client discovery. The Python and TypeScript packages replay their unchanged Go-recorded capability. Live Campaign Monitor authorization remains unverified.

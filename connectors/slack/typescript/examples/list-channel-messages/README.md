# Read one Slack channel history page

Run `npm ci` and `npm run build` in `connectors/slack/typescript`, then configure a Dex project connection named `slack-channel-history-reader` in Dex Web. The Slack OAuth installation needs the bot scopes in the connector README; this read uses the bot token's `channels:history` and `groups:history`, so invite the app to the channel first. Start `dexcli dev` and set `DEX_FLOW_SERVICE_ADDRESS` to its gRPC address. Run `npx tsx examples/list-channel-messages/main.ts` in one terminal, then `npx tsx examples/list-channel-messages/start.ts '{"channelId":"C0123456789","oldestTimestamp":"1710000000.000100","pageSize":15}'` in another. Keep provider tokens in Dex project credentials, never Flow input.

The Flow returns up to `pageSize` top-level messages, newest first, and a `nextCursor` while older messages remain; pass it back as `cursor` to read the next page. `pageSize` is 1 through 15 (blank or 0 reads 15), the most Slack returns to a non-Marketplace app. This example only reads a page and does not match a marker. An application that posted with `postChannelMessage` and got an uncertain outcome can bound `oldestTimestamp` to the time of its first attempt and search the returned `text` for its own marker, but only in messages whose `botId` or `userId` equals the bot ID or bot user ID from `getWorkspaceIdentity`, so a person quoting the marker is not mistaken for the post; the Go [channel marker search example](../../../go/examples/channel-marker-search/README.md) shows that reconciliation.

The Flow Definition Graph 2.0 source is [`flow/workflow.ts`](flow/workflow.ts). Its two application Step types each have one `dex:group` and one `dex:explanation` directive. The connector Step uses the static `ConnectionName`; only its `read` branch is wired, so other optional branches fail the Flow. Both Attributes are registered in the persistence schema. With `dexcli dev` running, `DEX_FLOW_SERVICE_ADDRESS=127.0.0.1:8801 npm run test:integration` runs this Flow on a real Dex Worker and Client against a local Slack HTTP stand-in. Live Slack authorization and Web API behavior for this example have not been verified.

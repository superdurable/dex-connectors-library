# HubSpot TypeScript connector

`@superdurable/connector-hubspot` provides Dex Steps for `searchObjects`, `getObject`, `upsertObject`, and `updateObject`. It supports HubSpot private app tokens and HubSpot OAuth. The connection resolves credentials at dispatch, refreshes OAuth tokens through the generated manifest driver, and retries one request after a rejected OAuth access token. The two writes are repeat-safe: upsert uses a unique HubSpot property and update replaces named property values.

The [search deals example](examples/search-deals/README.md) is a runnable Flow with a Worker entrypoint and static `hubspot-crm` connection name. Create that connection in Dex Web **Connections**. For private apps, open [HubSpot](https://app.hubspot.com/), choose **Development > Legacy apps > Create legacy app > Private**, grant the CRM read and write scopes listed in `connector.yaml`, and copy the access token from the app's **Auth** tab. For OAuth, choose a public legacy app or project app, register the redirect URI shown in Dex Web on the app's **Auth** tab, add the manifest scopes, enter the client ID and secret, and complete consent. Dex Web holds the credentials; they never enter Flow input or output.

From this directory, run `npm ci`, `npm run check`, and `npm run example:search`. To submit the sample input, run `npm run example:search:start -- examples/search-deals/input.example.json` in another terminal. Set `DEX_FLOW_SERVICE_ADDRESS` when Dex uses a nondefault port. `npm run test:integration` runs the same Flow through a real Dex Worker and Client against a local provider stand-in.

The package exports generated Config, Credentials, operation models, definitions, Step factories, and mock cases. Use `newProjectConnection(project, ConnectionName)` to bind the project connection, or `newConnection(new HubSpotClient(config, credentialSource), reference)` when constructing a client directly. The provider endpoint defaults to HubSpot's public API; `maxResponseBytes` defaults to one MiB.

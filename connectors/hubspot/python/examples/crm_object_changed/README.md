# CRM object changed Flow

This example polls one HubSpot object type with the `crmObjectChanged` Trigger and starts one `HubSpotCRMObjectChangePython` Flow per created or changed record. The Flow records the delivered change, reads the record back with `getObject`, and completes with its current values. `main.py` is the Worker entrypoint; `watcher.py` runs the Worker, the Client, and the durable poll runner on one event loop.

Create the static `hubspot-crm-watcher` connection in Dex Web **Connections** with a private app token or OAuth, as described in the [package README](../../README.md). The app needs the `crm.objects.<type>.read` scope of the watched type, which the authorization guide lists. Optionally set `pollInterval`, the delay between polls (at least 5s). Then save the `crm-object-changes` Trigger binding's **Watched object type**. The first start records existing records as a baseline and starts no Flow for them; restart the Worker after changing the type, which records a new baseline.

From `connectors/hubspot/python`, run `uv run python -m examples.crm_object_changed.main`. Set `DEX_FLOW_SERVICE_ADDRESS` for a nondefault Dex endpoint and `LOG_LEVEL=DEBUG` to see every poll and delivery. Each change is recorded in the binding's project Trigger inbox before the search cursor commits, so a restart neither misses nor repeats a change, and the Flow ID `hubspot-crm-object-change-<event ID>` keeps a redelivered change to one Flow.

With `dexcli dev` running, `DEX_FLOW_SERVICE_ADDRESS=<address> uv run pytest examples/crm_object_changed/integration_test.py` runs the example against `hubspot_search_fake.py`, an in-memory stand-in for HubSpot search: existing records stay a baseline, each change starts exactly one Flow, changes made while the process is stopped arrive after a restart, and a 429 with `Retry-After` pauses polling before the change is delivered. `tests/test_crm_object_changed_example.py` covers the mappers, the binding's picker unit, and project binding validation without Dex. Run `dexcli visualize --schema-version 2.0 examples/crm_object_changed/flow.py` to confirm that the analyzer reads the binding.

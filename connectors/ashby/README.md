# Ashby connector

The Go, Python, and TypeScript `getCandidate` Query reads one candidate's ID, name, and creation/update timestamps. Email, phone, resumes, and custom fields are excluded from Dex Results.

Go also provides `listCandidates` to page through candidate identities and `updateCandidate` to replace one candidate's display name. Both use the default one-hour retry budget; reads and absolute name replacement are safe to repeat. The Python and TypeScript packages retain only `getCandidate`.

Go also provides `addCandidateTag` and `removeCandidateTag` for existing candidate tags. Both set an absolute membership state and use the safe repeat tier. Find the non-secret tag UUID under **Admin > Organization Settings > Candidate Tags**, or through `candidateTag.list` with additional **Hiring Process read** permission; pass it as `tagId` with a candidate UUID. Blank IDs are invalid. The returned profile omits contact and resume details. See [candidate.addTag](https://developers.ashbyhq.com/reference/candidateaddtag) and [candidate.removeTag](https://developers.ashbyhq.com/reference/candidateremovetag).

Go `createCandidate` creates a candidate from a complete first and last display name, using a bounded `limited` send tier. Ashby has no documented idempotency key or stable lookup identity for a name-only create, so a timeout or lost response can cause a duplicate candidate on resend. The connector permits at most three possible sends and selects `uncertain` if the cap is reached without a confirmed result. Use a disposable candidate for a live test. See [candidate.create](https://developers.ashbyhq.com/reference/candidatecreate).

Go `searchCandidates` searches by a candidate name, a complete email address, or both. At least one search field is required; `limit` is 1–100, with zero using Ashby's default of 100. Find names or email addresses under **Candidates > Search** in Ashby. Search results expose only candidate IDs, names, and timestamps. See [candidate.search](https://developers.ashbyhq.com/reference/candidatesearch).

Go `listCandidateProjects` pages through project identities linked to a candidate; `addCandidateProject` and `removeCandidateProject` set the absolute membership state and use the safe repeat tier. Find a project under **Sourcing > Projects** in Ashby or retrieve an associated project ID through `candidate.listProjects`; pass its non-secret UUID as `projectId`. Blank IDs are invalid. Project descriptions and member details are omitted from results. See [candidate.listProjects](https://developers.ashbyhq.com/reference/candidatelistprojects), [candidate.addProject](https://developers.ashbyhq.com/reference/candidateaddproject-1), and [candidate.removeProject](https://developers.ashbyhq.com/reference/candidateremoveproject-1).

Go `listCandidateNotes` pages through a candidate's note IDs, timestamps, and privacy flags; it sends an explicit page limit of 100 when `limit` is zero so Ashby's legacy 500-note default is avoided. `createCandidateNote` writes a plaintext note up to 8192 bytes without notifications or private-note permissions. Do not put secrets in the note. Creation uses a `limited` three-send Fence because Ashby has no documented note idempotency key and duplicate notes can result after an unknown outcome; the note content and author are never returned. See [candidate.listNotes](https://developers.ashbyhq.com/reference/candidatelistnotes) and [candidate.createNote](https://developers.ashbyhq.com/reference/candidatecreatenote).

Go `listJobs`, `getJob`, and `searchJobs` read bounded job summaries with **Jobs read** permission. Find a job UUID under **Jobs > Jobs**; search by title or requisition ID, and use a limit from 1 to 100. `createJob` needs a title and the non-secret team and location UUIDs shown in Ashby job settings; it needs **Jobs write** permission. Creation uses a three-send Fence and can select `uncertain` after an unconfirmed response because Ashby does not document a job idempotency key. `updateJobTitle` and `setJobStatus` replace absolute values and safely repeat. Status is `Draft`, `Open`, `Closed`, or `Archived`; a close reason UUID is optional only for `Closed`. See [job.list](https://developers.ashbyhq.com/reference/joblist), [job.create](https://developers.ashbyhq.com/reference/jobcreate), and [job.setStatus](https://developers.ashbyhq.com/reference/jobsetstatus).

Go `listApplications` and `getApplication` expose only application, candidate, job, and stage IDs, status, and timestamps; they need **Candidates read**. `createApplication` considers an existing candidate for a job and needs **Candidates write**. It uses a three-send Fence because Ashby documents no application idempotency key. `changeApplicationStage` is also limited to three possible sends because stage automations may run; it reads the application back before resending when a prior attempt might have succeeded. `transferApplication` sends `startAutomaticActivities:false` and sets an absolute job, plan, and stage. `setApplicationSource` replaces one source UUID. These writes need **Candidates write**. `deleteApplication` needs **Candidates delete**. Find IDs from **Candidates > Search**, **Jobs > Jobs**, the job's interview plan, and **Admin > Organization Settings > Sources**; blanks are invalid. See [application.list](https://developers.ashbyhq.com/reference/applicationlist), [application.create](https://developers.ashbyhq.com/reference/applicationcreate), [application.changeStage](https://developers.ashbyhq.com/reference/applicationchangestage), and [application.transfer](https://developers.ashbyhq.com/reference/applicationtransfer).

## Connect

In [Ashby](https://app.ashbyhq.com), an administrator opens **Admin > API Keys** and creates an API key with **Candidates read** or **Jobs read** permission for the reads used, plus the matching **Candidates write** or **Jobs write** permission for writes. `deleteApplication` also requires **Candidates delete**. Copy the complete opaque secret into the Dex Web connection's `api_key` field. The connector sends it as the HTTP Basic username with an empty password. Revoke or rotate the key from the same page. Confidential candidates require the additional confidential jobs/projects permission. See [Ashby authentication](https://developers.ashbyhq.com/reference/authentication).

Leave `baseUrl` blank for `https://api.ashbyhq.com`. `timeout` is a per-request Go duration, and `maxResponseBytes` is a byte limit; blank uses the displayed defaults. Find the non-secret candidate UUID in Ashby or from `candidate.list` and pass it as `candidateId`; blank is invalid. See [candidate.info](https://developers.ashbyhq.com/reference/candidateinfo) and [API response conventions](https://developers.ashbyhq.com/reference/responses).

## Examples and verification

Run the [Go](go/examples/candidate-inspection/README.md), [Python](python/examples/candidate_inspection/README.md), or [TypeScript](typescript/examples/candidate-inspection/README.md) candidate inspection Flow with the static `ashby` connection. Go-recorded conformance checks exact requests, branches, retries, and outputs for each implemented language capability. Local integration tests exercise real Dex with fixture providers. Real Ashby authorization, listing, retrieval, updating, and tag writes remain unverified.

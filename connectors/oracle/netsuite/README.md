# Oracle NetSuite connector

The Go connector lists, gets, creates, updates, and deletes customers and vendors through [NetSuite REST Web Services](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/chapter_1540811107.html). `listCustomers` and `listVendors` accept a page size of 1–1000 and a zero-based offset that is a multiple of the page size. Lookup, update, and delete operations accept a numeric internal ID. Create operations need a displayed entity ID and company name. Customer creation also needs a numeric subsidiary internal ID; vendor creation accepts one when the account uses OneWorld and leaves it blank otherwise. The existing `getCustomer` Query is also implemented in [Python](python/) and [TypeScript](typescript/); those packages replay their declared operations from [Go-recorded provider scenarios](../../../conformance/connectors/oracle/netsuite/scenarios.json).

Configure an OAuth 2.0 integration with the `rest_webservices` scope and customer and vendor read, create, edit, and delete role permissions for the Go operations. Register the exact Dex Web redirect URI. Copy the account-specific REST, authorization, and token URLs from the account ID; [Oracle's OAuth setup tutorial](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/section_0602033701.html) documents their formats. NetSuite uses Basic client authentication for token exchange. Keep the client secret and tokens in Dex credentials.

HTTP 408, 429, 5xx, and transport failures retry. Customer and vendor creation have a three-send cap and can return an uncertain outcome when the provider may have accepted a request without returning its ID. A missing record, provider rejection, malformed response, or local configuration defect selects an optional branch. Runnable examples for [Go](go/examples/customer-inspection/README.md), [Python](python/examples/customer_inspection/README.md), and [TypeScript](typescript/examples/customer-inspection/README.md) wire only the happy path and include real Dex mock integration tests. Live OAuth consent and record writes require a user-controlled NetSuite account and have not been verified.

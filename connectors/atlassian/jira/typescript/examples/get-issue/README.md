# Read one Jira issue

`GetJiraIssueFlow` reads one issue through the static `jira-triage` connection. The Flow stores only the requested issue key and the returned issue view. Requested additional fields are raw Jira JSON, so select only fields the application may persist.

Create an Atlassian OAuth 2.0 (3LO) application using the [connector setup guide](../../../../README.md#atlassian-setup). Register the Dex Web redirect URI, enable Jira API with `read:jira-work` and `write:jira-work`, and authorize the Jira site. Set `cloudId` with the site picker or the UUID at `https://<your-site>.atlassian.net/_edge/tenant_info`. Leave the gateway URL blank for Atlassian's public API. Name the Dex connection `jira-triage`.

Start `dexcli dev` and set `DEX_FLOW_SERVICE_ADDRESS` to its gRPC address. Set `DEX_CONNECTOR_CONFIG_FILE` to the mode-0600 project `connections.json` generated by Dex Web. From `connectors/atlassian/jira/typescript`, run the Worker:

```sh
npm run example:get
```

In another terminal with the same environment, edit `input.example.json` to name an issue the connection can browse, then start the Flow:

```sh
npm run example:get:start -- examples/get-issue/input.example.json
```

The starter prints the issue view. The input file contains no credentials.

The integration test runs the same Flow against a real Dex stack and a local Jira stand-in. Bind Dex to ports in your assigned range and run:

```sh
DEX_FLOW_SERVICE_ADDRESS=127.0.0.1:38301 npm run test:integration
```

Generate and lint a strict Flow Definition Graph 2.0 with Dex CLI 1.28.0 or newer:

```sh
npm run build
npm install --prefix examples/get-issue --no-save --no-package-lock --ignore-scripts .
cd examples/get-issue
dexcli visualize flow/workflow.ts --language typescript --schema-version 2.0 --lint app --json --out - --open=false
```

This example's Dex integration uses a local stand-in. Live Atlassian authorization, site selection, and API behavior remain unverified.

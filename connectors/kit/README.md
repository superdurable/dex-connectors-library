# Kit connector

The Go, Python, and TypeScript connectors list one cursor page of subscribers with `listSubscribers` and read one subscriber with `getSubscriber`. Go also provides `upsertSubscriber`, `listTags`, `createTag`, `tagSubscriber`, and `removeTagFromSubscriber`. Subscriber results contain only ID, email address, first name, and lifecycle state. Subscriber custom-field values, attribution, and location stay out of those results. List results use the provider's `end_cursor` for the next page and request `slim=true` for subscribers.

For automation of your own account, open [Kit Developer settings](https://app.kit.com/account_settings/developer_settings), choose Add a new key under V4 API Keys, and copy the one-time value into the Dex Web connection's secret `api_key` field. The legacy V3 API Secret does not work. The connector sends the key only in the `X-Kit-Api-Key` header. Leave `baseUrl` blank for the displayed API v4 default. Kit requires OAuth for public App Store integrations. See [authentication](https://developers.kit.com/api-reference/authentication), [list subscribers](https://developers.kit.com/api-reference/subscribers/list-subscribers), and [get a subscriber](https://developers.kit.com/api-reference/subscribers/get-a-subscriber).

All new Go writes use safe repeat semantics: [subscriber creation](https://developers.kit.com/api-reference/subscribers/create-a-subscriber) upserts by email, [tag creation](https://developers.kit.com/api-reference/tags/create-a-tag) reuses a case-insensitive name, and [tag assignment](https://developers.kit.com/api-reference/tags/tag-a-subscriber) returns an existing association on repeats. [Tag removal](https://developers.kit.com/api-reference/tags/remove-tag-from-subscriber) is a repeatable delete. Use a valid subscriber email, a nonblank tag name, and positive IDs from Kit's **Grow > Subscribers** and tag pages. A tag application can trigger Kit automations configured for that tag. A blank cursor starts the first list page; zero `perPage` uses 20.

Queries and mutations retry transport failures, HTTP 429, request timeout, and server failures. `getSubscriber` and tag membership mutations select `notFound` on a definitive 404. Provider rejections and malformed or oversized responses select optional branches. The [subscriber-inspection Flow](go/examples/subscriber-inspection/README.md) is the runnable consumer and also lists one page of tags. Python and TypeScript replay only their published read capabilities from the Go-recorded scenarios. Live Kit authorization remains unverified.

Go provides `listCustomFields`, `createCustomField`, `updateCustomField`, and `deleteCustomField` through Kit's [custom-field API](https://developers.kit.com/api-reference/custom-fields/list-custom-fields). In Kit, open **Settings > Custom Fields** to find the numeric field ID and label; IDs must be positive. Listing uses a cursor, with `perPage` from 1–1000 (zero uses 20) and blank `after` starting the first page. Create requires a nonblank label of at most 255 bytes and reuses an existing label, so repeats are safe. Update replaces a label and changes its personalization key while preserving its HTML field name; update any email templates that reference the old key. Delete removes subscriber values for that field. Kit v4 documents no direct custom-field get endpoint; list pages to locate a field. Live provider permissions and responses remain unverified.

Go provides `listForms`, `listFormSubscribers`, and `addSubscriberToForm` through Kit's [forms API](https://developers.kit.com/api-reference/forms/list-forms). In Kit, open **Grow > Landing Pages & Forms** to find a form or landing-page ID; use **Grow > Subscribers** for the numeric subscriber ID. IDs must be positive. Listing uses an opaque `after` cursor and `perPage` from 1–1000 (zero uses 20). Form subscriber listing requests slim records and returns only identity, name, and state. Adding a subscriber requires an absolute HTTP(S) signup `referrer` URL; the subscriber must already exist, and archived, deleted, or restricted forms reject additions. Kit returns the existing form subscription on a repeat, so the write uses safe repeat semantics. A form addition can trigger configured Kit automations. Live form permission and signup behavior remain unverified.

Go provides `listSequences`, `listSequenceSubscribers`, and `addSubscriberToSequence` through Kit's [sequence API](https://developers.kit.com/api-reference/sequences/list-sequences). Open Kit **Send > Sequences** for a numeric sequence ID and **Grow > Subscribers** for a subscriber ID; IDs must be positive. Both list operations accept `perPage` from 1–1000 (zero uses 20) and an opaque `after` cursor; blank starts the first page. An existing subscriber can join a sequence, which may start scheduled emails. Kit returns an existing active membership on a repeat, but sequences configured for re-entry can cause additional sends after completion. Enrollment therefore uses a limited three-send budget and can select `uncertain`; inspect sequence membership and delivery before another enrollment. Sequence listing exposes the `active` and `repeat` settings to help callers decide. The Go module requires released Connector SDK v0.38.0 and Dex Go SDK v1.26.0 for the bounded dispatch fence; the intervening SDK releases have no relevant connector breaking change beyond the Dex Go SDK minimum. Live sequence delivery remains unverified.

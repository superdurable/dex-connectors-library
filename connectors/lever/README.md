# Lever connector

The Go connector reads and manages Lever opportunities. `listOpportunities` pages through selected opportunity fields, `getOpportunity` reads one, `updateOpportunityStage` replaces its stage, `setOpportunityArchiveState` archives or unarchives it, and `createOpportunity` creates a candidate opportunity. Python and TypeScript currently implement only `getOpportunity`. Contact details, resumes, notes, and other profile fields are excluded from read Results.

## Connect

In [Lever](https://hire.lever.co), open **Settings > Integrations and API > API Credentials** and create an API key with opportunity read access. Enable opportunity write access when using the Go mutations. Copy the complete opaque secret into Dex Web `api_key`; blank is invalid. The connector uses HTTP Basic authentication with the key as username and an empty password. Revoke or rotate it on the same page. See [Lever API authentication](https://hire.lever.co/developer/documentation).

Leave `baseUrl` blank for `https://api.lever.co/v1`. `timeout` is a per-request Go duration and `maxResponseBytes` is a byte limit; blank uses their displayed defaults. Find the non-secret opportunity UID in Lever or the list opportunities response and pass it as `opportunityId`; blank is invalid. See [Retrieve a single opportunity](https://hire.lever.co/developer/documentation).

For `listOpportunities`, leave `offset`, `email`, and `stageId` blank to include the first page and all visible contacts and stages; `nextOffset` supplies the following page's opaque cursor. `limit` is an item count from 1 to 100, or zero for Lever's default. For `updateOpportunityStage`, find the destination stage UID under Lever **Settings > Pipeline** or through the [stages API](https://hire.lever.co/developer/documentation); a blank UID is invalid. For `setOpportunityArchiveState`, find an archive reason UID under **Settings > Pipeline > Archive Reasons** or through the [archive reasons API](https://hire.lever.co/developer/documentation); blank `reasonId` unarchives the opportunity. For `createOpportunity`, find the acting user UID under **Settings > Users** or through the [users API](https://hire.lever.co/developer/documentation), then supply a full candidate name and email address. These input values are not credentials; `performAsUserId`, `name`, and `email` cannot be blank.

`createOpportunity` uses a durable single-dispatch fence with `repeatOnUnknown: limited` and `maxSends: 3`. Lever offers no create idempotency key or reliable lookup by a call-specific marker. A lost create result may therefore yield a duplicate opportunity on retry; an unresolved outcome at the cap selects `uncertain`. The stage and archive replacements use `repeatOnUnknown: safe` and read back the resulting opportunity. Queries use `safe`.

## Examples and verification

Run the [Go](go/examples/opportunity-inspection/README.md), [Python](python/examples/opportunity_inspection/README.md), or [TypeScript](typescript/examples/opportunity-inspection/README.md) opportunity inspection Flow with the static `lever` connection. The Go example also lists opportunities in the selected stage. Go-recorded conformance checks exact requests, branches, retries, and outputs for every Go operation; Python and TypeScript replay only their declared `getOpportunity` capability. Local integration tests exercise real Dex with fixture providers. Real Lever authorization, reads, and writes remain unverified.

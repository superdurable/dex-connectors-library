# Lever connector

The Go connector reads and manages Lever opportunities, job postings, notes, interviews, and users. `listOpportunities` pages through selected opportunity fields, `getOpportunity` reads one, `updateOpportunityStage` replaces its stage, `setOpportunityArchiveState` archives or unarchives it, and `createOpportunity` creates a candidate opportunity. `getPosting` and `listPostings` read selected posting fields; `createPosting` creates a draft with required categories; `updatePosting` sets an absolute title and state. `getNote` and `listNotes` return note metadata; `createNote`, `updateNote`, and `deleteNote` manage notes created through the API. `getInterview` and `listInterviews` return schedule metadata; `createInterview`, `updateInterview`, and `deleteInterview` manage interviews on externally managed panels. `getUser` and `listUsers` return user role and activation metadata; `createUser`, `updateUser`, `deactivateUser`, and `reactivateUser` manage users. Python and TypeScript currently implement only `getOpportunity`. Contact details, resumes, note bodies, and other profile fields are excluded from read Results.

## Connect

In [Lever](https://hire.lever.co), open **Settings > Integrations and API > API Credentials** and create an API key with opportunity read access. Enable opportunity write access when using the Go mutations. Copy the complete opaque secret into Dex Web `api_key`; blank is invalid. The connector uses HTTP Basic authentication with the key as username and an empty password. Revoke or rotate it on the same page. See [Lever API authentication](https://hire.lever.co/developer/documentation).

Leave `baseUrl` blank for `https://api.lever.co/v1`. `timeout` is a per-request Go duration and `maxResponseBytes` is a byte limit; blank uses their displayed defaults. Find the non-secret opportunity UID in Lever or the list opportunities response and pass it as `opportunityId`; blank is invalid. See [Retrieve a single opportunity](https://hire.lever.co/developer/documentation).

For `listOpportunities`, leave `offset`, `email`, and `stageId` blank to include the first page and all visible contacts and stages; `nextOffset` supplies the following page's opaque cursor. `limit` is an item count from 1 to 100, or zero for Lever's default. For `updateOpportunityStage`, find the destination stage UID under Lever **Settings > Pipeline** or through the [stages API](https://hire.lever.co/developer/documentation); a blank UID is invalid. For `setOpportunityArchiveState`, find an archive reason UID under **Settings > Pipeline > Archive Reasons** or through the [archive reasons API](https://hire.lever.co/developer/documentation); blank `reasonId` unarchives the opportunity. For `createOpportunity`, find the acting user UID under **Settings > Users** or through the [users API](https://hire.lever.co/developer/documentation), then supply a full candidate name and email address. These input values are not credentials; `performAsUserId`, `name`, and `email` cannot be blank.

For postings, find a posting UID in Lever **Jobs** or `listPostings`; blank is invalid. A blank `state` filter includes all visible states. `createPosting` requires a title, acting user UID, and team, department, and location labels from Lever **Settings > Tags**; it creates a `draft`. `updatePosting` requires the posting UID, acting user UID, title, and a state such as `draft` or `published`. Use the [Lever posting API](https://hire.lever.co/developer/documentation) to confirm available states and published distribution behavior.

For notes, find the opportunity UID in **Candidates** or `listOpportunities`, and the note UID in its profile or `listNotes`; both are non-secret UUIDs, and blank is invalid. `createNote.value` is the required text; `updateNote.values` is a nonempty array of all replacement comments, so include every comment you intend to retain. Lever can update or delete only notes originally created through its API. See the [Lever notes API](https://hire.lever.co/developer/documentation).

For interviews, use `listOpportunities` for the opportunity UID, Lever **Interviews** or `listInterviews` for the interview UID, **Settings > Users** for the acting and interviewer user UIDs, and an externally managed panel UID from the [Lever panels API](https://hire.lever.co/developer/documentation). All IDs are non-secret UUIDs and blank is invalid. The write input needs at least one interviewer UID, a positive Unix-millisecond `date`, and a positive `durationMinutes`. `subject`, `note`, and `location` are optional; blank clears them on full replacement. Lever permits API create, update, and delete only on externally managed panels. Deleting the last interview also deletes its panel.

For users, find the user UID under Lever **Settings > Users** or `listUsers`; blank is invalid. An optional exact `email` filter narrows `listUsers`, while `includeDeactivated` includes inactive users. `createUser` needs a preferred name, email, and explicit access role; Lever does not send an invitation. `updateUser` replaces the complete supplied profile, so include `externalDirectoryId`, `jobTitle`, `managerId`, and every `linkedContactId` you want to retain. Changing `accessRole` to `interviewer` can remove followed profiles. Deactivation prevents login; reactivation restores it. See the [Lever users API](https://hire.lever.co/developer/documentation).

`createOpportunity`, `createPosting`, `createNote`, `createInterview`, and `createUser` use durable single-dispatch fences with `repeatOnUnknown: limited` and `maxSends: 3`. Lever offers no create idempotency key. `createUser` first reads back by email after an unknown result; other creates lack a reliable call-specific lookup, so a lost result may yield a duplicate on retry. An unresolved outcome at the cap selects `uncertain`. Absolute replacements, deletes, and activation changes use `repeatOnUnknown: safe`. Queries use `safe`.

## Examples and verification

Run the [Go](go/examples/opportunity-inspection/README.md), [Python](python/examples/opportunity_inspection/README.md), or [TypeScript](typescript/examples/opportunity-inspection/README.md) opportunity inspection Flow with the static `lever` connection. The Go example also lists opportunities in the selected stage and provides posting, note, interview, and user list Flows. Go-recorded conformance checks exact requests, branches, retries, and outputs for every Go operation; Python and TypeScript replay only their declared `getOpportunity` capability. Local integration tests exercise real Dex with fixture providers. Real Lever authorization, reads, and writes remain unverified.

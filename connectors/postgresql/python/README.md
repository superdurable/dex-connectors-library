# PostgreSQL Python connector

`dex-connector-postgresql` exposes `query`, `execute`, and `executeNonIdempotent` Steps (`new_query_step`, `new_execute_step`, `new_execute_non_idempotent_step`) for parameterized PostgreSQL statements. Configure a named PostgreSQL connection in Dex Web, then use the same name when constructing the Worker and Step factories. The provider client uses one native Psycopg connection and one transaction per invocation; passwords are resolved for each call.

The Python package follows the Go connector's branch and retry contract. `query` runs read-only and may return `truncated`. `execute` commits one repeat-safe write and can roll back on row limits; it is `repeatOnUnknown: safe`, so a COMMIT whose outcome is unknown returns Retry and the statement runs again, and it never selects `uncertain`. `executeNonIdempotent` takes the same input for a statement that must not run twice. It is `repeatOnUnknown: unsafe`: it records a single-dispatch claim in the sync Step heartbeat before COMMIT, selects `uncertain` when COMMIT may have reached PostgreSQL, and selects `uncertain` without connecting on a later attempt after such a COMMIT or a lost Worker. A proven rollback returns Retry, and an unreadable checkpoint returns Retry without connecting. See the [connector README](../README.md) for type mapping, TLS choices, and setup guidance.

`new_connection_with_operations` accepts the new operation as the keyword-only `execute_non_idempotent` argument; a connection built without it raises `ValueError` when an `executeNonIdempotent` Step is constructed.

Every statement is parsed and described by PostgreSQL before binding values, including statements with no parameters. PostgreSQL rejects multiple statements in one call. A placeholder count mismatch or duplicate result column selects `defect` before execution. Each invocation has a client deadline of `connectTimeout + statementTimeout + 5` seconds; a timeout after COMMIT is sent returns Retry for `execute` and selects `uncertain` for `executeNonIdempotent`. Psycopg 3.3.6 or newer bounds its wait after cancellation on an unresponsive server when libpq is 17 or newer.

The connection requests UTF8 client encoding so statements, parameters, and returned text round-trip across databases with other encodings. A statement containing only SQL comments completes with no rows; `execute` reports an empty command.

`verify-full` trusts the system root store unless `PGSSLROOTCERT` names a private CA file. `verify-ca` requires `PGSSLROOTCERT` on the Worker because libpq cannot use its system root store without hostname verification. A missing or invalid root certificate or a hostname mismatch selects a terminal authentication failure.

JSON and JSONB values are returned as JSON values when Python can encode every number without changing its text and every object key is unique. A number such as `1.10`, a high-precision decimal, `1e400`, or a duplicate object key selects `invalidResponse` and names the column; the Python SDK JSON codec cannot carry PostgreSQL's raw JSON text. Other scalar mappings follow the Go connector, including unbounded timestamp text and trimmed fractional seconds.

The checked-in `examples/record_refund` Flow exercises all three operations with the generated mock connection. Real PostgreSQL integration tests run in CI's service container using `POSTGRESQL_CONNECTOR_TEST_*` variables. The Flow still covers the public operation path; the protocol and value regressions are checked through the direct provider integration test.

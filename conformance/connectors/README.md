# Connector operation conformance

Each `conformance/connectors/<directory>/scenarios.json` replays provider responses through the Go connector and its Python and TypeScript ports. The porter authors scenario identity (`name`, `operation`, `callId`), `input`, optional `attempts` and `priorHeartbeat`, and ordered provider responses (`status`, `headers`, `body`) or `transportFailure` (`before-send` or `after-send`). Use inert placeholder credentials. Keep provider data realistic and nonempty where the successful operation returns data.

From the connector's `go/` directory, run `CONNECTOR_CONFORMANCE_MODE=record GOWORK=off go test . -run '^TestConnectorConformance$' -count=1`. The generated Go reference test replaces all derived expectations in `scenarios.json`: each request's method and path, every query and form value, full JSON body or decoded Gmail MIME, connector-sent headers, the production idempotency key, intermediate retries, final branch and failure kind, retry delay, uncertainty, exact Go-marshaled output, and provider request count. Commit the resulting fixture. A normal Go test records again in memory and fails if any committed expectation differs. Do not hand-edit derived expectations.

Every scenario must match the Go recording; `pending` is rejected. The union of inputs for each operation must set every Go `Input` field to a nonzero value at least once, including optional fields. Every non-retry branch has an exact `output`; an empty or null output is still recorded. Each operation needs separate 429 and 5xx Retry scenarios whose classified status is the first exchange of the final attempt, a transport-failure scenario, each declared branch, and uncertainty when declared. Intermediate decisions record cumulative `exchangeCount`, which identifies the start of the final attempt. Cover additional Go-tested duplicate-safety and read-back behavior.

The Python and TypeScript runners compare requests and production Dex SDK codec outputs by exact equality. SDK field defaults determine omission; the runners do not re-encode values by hand. They invoke mutations through the production SDK path, which derives the idempotency key from the operation and Call ID; they never inject the fixture key. Gmail `requestBody.$rawMime` contains the full decoded MIME message, including subject, recipients, and body. The runners ignore transport-added `Host`, `Connection`, `Content-Length`, and `Accept-Encoding` headers, plus unmodified HTTP client defaults for `Accept` and `User-Agent`. `requestCount` includes requests that reached the provider, including read-backs and after-send failures; before-send failures consume an attempt but do not count as provider requests.

Run `make test-connector-conformance CONNECTOR_DIRECTORY=connectors/<directory>` locally. `connectorctl generate --check` checks the generated Go test. CI runs all fixture-backed changed connectors and `python3 script/connector_conformance.py --mutation-self-test`, which corrupts representative branch, output, request, MIME, idempotency, read 5xx, and pending fields to prove the runners reject them. New or edited Python and TypeScript packages require fixtures. Existing packages without fixtures warn `missing conformance (legacy)` on Go-only changes. Provider replay supplements the connector's runnable Dex example; it is not live-provider verification.
